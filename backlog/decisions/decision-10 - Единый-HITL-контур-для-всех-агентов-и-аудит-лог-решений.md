## Context

Human-in-the-loop реализован серьёзно, но только для одного пути: AI Studio с Claude CLI через
`--permission-prompt-tool` и встроенный MCP-сервер. Swarm-агенты запускаются с
`--dangerously-skip-permissions` и находятся вне контура. Решения об одобрении не логируются
нигде, кроме текста сессии в памяти. Удалённые клиенты не получают событие о запросе, а
решение с телефона одобряет верхний запрос в очереди без сверки идентификатора.

Для ADE, где несколько агентов с разными ролями работают параллельно, а человек может быть за
другим компьютером или в Telegram, нужен один механизм одобрений с очередью, адресацией и
историей.

## Decision

1. **Один HITL-контур для всех движков.** Любой агент, запускаемый ProjectHub (AI Studio,
   Swarm, Handoff, назначенная задача), проходит через тот же `permission_prompt` инструмент
   встроенного MCP-сервера. Для Claude CLI это `--permission-prompt-tool`; для других CLI
   используется их эквивалент или обёртка-прокси инструментов; для API-движка проверка в
   собственном tool-loop. `--dangerously-skip-permissions` допускается только как явный,
   залогированный fallback при недоступном HITL-сервере и включённом пользователем auto-approve.
2. **Очередь запросов с идентификаторами.** Каждый запрос имеет `requestId`, `sessionId`,
   `agentId`, `role`, `hostId`, тип инструмента, полезную нагрузку (команда, путь, дифф) и
   срок ожидания. Решение всегда адресуется по `requestId`; решение «по верхнему в очереди»
   запрещено. Очередь персистится, чтобы пережить перезапуск, и отменяется при завершении
   сессии.
3. **Политики auto-approve привязаны к роли** (см. [[decision-9]]): allow/deny-списки
   инструментов, путей и команд, лимит времени команды. Глобальные настройки пользователя
   остаются как значения по умолчанию, роль может только сужать их, но не расширять запись вне
   корня проекта.
4. **Аудит-лог решений.** Каждое решение (кем принято: пользователь локально, пользователь
   удалённо с `deviceId`, авто-политика с именем правила; что именно одобрено; результат
   выполнения) пишется в `<userData>/audit/hitl-<yyyy-mm>.jsonl` и доступен в UI как история.
   Имена секретов и содержимое файлов в аудит не попадают, только пути и хэши.
5. **Единая шина событий.** Запрос, решение, завершение агента, ошибка публикуются как события
   `hitl:*` и `agent:*`, на которые подписаны рендерер, Remote Control (телефон, другой ПК),
   Telegram-бот и системные уведомления (см. [[decision-13]]). Ответ может прийти с любого
   подписчика, первый ответ по `requestId` выигрывает, остальные получают «уже решено».

## Consequences

- Плюс: одинаковое поведение и один UI одобрений для всех агентов и всех устройств.
- Плюс: история решений позволяет разбирать инциденты и обучать политики auto-approve.
- Минус: агенты в Swarm станут медленнее, если политики роли не настроены. Стартовые роли
  поставляются с разумными allow-списками (чтение, тесты, сборка без сети).
- Минус: очередь и аудит увеличивают объём состояния на диске; нужны ротация и лимиты.
- Реализация: TASK-57, удалённая часть в TASK-65, уведомления в TASK-63.
