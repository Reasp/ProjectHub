## Context

ProjectHub работает как командный центр для агентов, которые выполняют задачи минутами и
часами и периодически ждут решения человека. При этом в приложении нет ни системного трея, ни
уведомлений уровня ОС, ни звука. Единственный внешний канал это Telegram-сообщение о падении
процесса. Если окно свёрнуто или пользователь за другим компьютером, он не узнаёт, что агент
закончил, ждёт одобрения или упал.

## Decision

1. **Единая шина событий в main-процессе** (`eventBus`), в которую публикуют все сервисы:
   `agent:started|finished|failed`, `hitl:requested|decided|expired`, `swarm:finished`,
   `process:crashed`, `pr:created|checksFailed`, `remote:deviceConnected`. Событие имеет
   `severity`, `projectPath`, `hostId`, краткий текст и действие по клику (открыть задачу,
   очередь HITL, арену).
2. **Подписчики шины**: рендерер (тосты и бейджи), системный трей с иконкой состояния
   (idle, working, needs-attention) и меню быстрых действий, Electron `Notification` с
   кнопками «Разрешить/Отклонить» для HITL там, где ОС это поддерживает, звуковой сигнал
   (настраиваемый, по умолчанию только для `needs-attention`), Telegram-бот (push с inline-кнопками
   решения), Remote Control (рассылка доверенным устройствам и федеративным хостам).
3. **Правила доставки настраиваются пользователем** по типу события и каналу: «HITL всегда в
   Telegram», «завершение агента только в трее», «тихие часы». Дедупликация: одно событие не
   приходит на одно устройство дважды, решение HITL с любого канала закрывает уведомление на
   остальных.
4. **Закрытие окна сворачивает в трей**, а не завершает агентов; полный выход через меню трея с
   подтверждением, если есть активные сессии.
5. Telegram-бот запускается и останавливается самим приложением через `processManager` при
   заданном токене, а не вручную отдельной командой.

## Уточнения по факту реализации (TASK-63)

1. **Шина уже была** — `appEventBus` создан в TASK-57 с `hitl:*` и `agent:*`. Добавлены только
   недостающие типы: `swarm:finished`, `process:crashed`, `pr:created`, `pr:checksFailed`,
   `remote:deviceConnected` (`electron/services/hitlTypes.ts`). `severity`, текст и действие по
   клику в самом событии не хранятся: события остаются «фактами предметной области», а в
   уведомление их превращает чистая функция `describeBusEvent` (`notificationRules.ts`). Так
   правила доставки тестируются без Electron, а издателям не приходится знать про UI.
2. **Разделение «правила/эффекты»**: `notificationRules.ts` — матрица каналов, тихие часы,
   дедупликация, тексты (чистый модуль, unit-тесты); `notificationService.ts` — единственный
   подписчик шины, который исполняет доставку. Настройки лежат в `<userData>/notifications.json`.
3. **Кнопки решения в системном уведомлении — только macOS** (`Notification.actions`). На Windows
   и Linux клик по уведомлению открывает Центр решений; матрица возможностей отдаётся в UI как
   `capabilities.osActions`, и об ограничении сказано текстом в настройках, а не умолчанием.
4. **Звук синтезируется WebAudio** (`src/lib/notificationSound.ts`), а не проигрывается из файла:
   не нужно тащить аудиоассет и решать, где он лежит в упакованном приложении. Решение «звучать
   ли» принимает main (матрица + тихие часы), рендерер только играет тон.
5. **Иконки трея вшиты в код как base64-PNG** (`trayIcons.ts`, генератор `scripts/gen-tray-icons.mjs`):
   трей создаётся до загрузки окна и одинаково работает в dev и в упакованном приложении, где
   `public/` уже внутри `app.asar`.
6. **Тихие часы не глушат трей.** Молчат `os`, `sound`, `telegram`; иконка состояния продолжает
   показывать `needs-attention`, иначе утром не видно, что агент ждал всю ночь.
7. **Подтверждение выхода — нативный `dialog.showMessageBox` main-процесса**, а не модалка
   рендерера: выход вызывается из меню трея, когда окно скрыто и рендерер может быть не готов.
   Запрет на `window.confirm` (TASK-48) это не нарушает — он про рендерер.
8. **Telegram: push шлёт main, кнопки ловит бот.** Сообщение с inline-кнопками отправляет
   `telegramService` напрямую через Bot API; нажатие приходит только polling-процессу бота, и он
   применяет решение по `requestId` через новый авторизованный эндпоинт Remote Control
   `POST /api/hitl/decide` (рядом — `GET /api/hitl/pending`). Так решение с любого канала проходит
   через тот же `hitlService.decide`, а второе нажатие получает 409 «уже решено».
9. **Реализация бота переехала в `electron/workers/telegramBot.mjs`**: только каталог воркеров
   попадает в упакованное приложение, поэтому `processManager` может его запустить
   (`ELECTRON_RUN_AS_NODE` + `process.execPath`, системный `node` не требуется).
   `scripts/telegram-bot.mjs` остался тонкой обёрткой для `npm run telegram-bot`. Секреты боту
   передаются окружением (`PROJECTHUB_BOT_ENV_ONLY=1` отключает чтение `.projecthub-telegram.json`).
10. **Служебные процессы ProjectHub** запускаются из `<userData>/services` и показываются во
    вкладке «Процессы» отдельной секцией: демон бота не принадлежит ни одному проекту.

## Consequences

- Плюс: агентная модель работы становится реально «отпустил и вернулся по сигналу».
- Плюс: один источник событий для всех каналов, включая федерацию.
- Минус: системные уведомления с кнопками ведут себя по-разному на Windows и macOS;
  fallback это открыть окно на нужном экране.
- Минус: шум. Настройки доставки и «тихие часы» обязательны в первой же версии.
- Реализация: TASK-63 (зависит от очереди HITL в TASK-57), см. [[decision-10]].
- Долг: доставка уведомлений федеративным хостам ограничена рассылкой доверенным устройствам
  текущего хоста — каталог хостов появится в TASK-66.
