## Context

Ревизия от 2026-09-10 ([[decision-7]], [[decision-8]]) показала три дефекта Swarm Arena:

- Сессии жили только в `Map` внутри `agentFleetService`. Каталог `~/.projecthub/swarms`
  создавался, но в него ничего не писалось. После перезапуска приложения `swarm:list` был
  пуст, а worktree и ветки `swarm/*` оставались осиротевшими без связи с сессией.
- `agent.logs[]` и `agent.liveOutput` росли без ограничения. Сессия целиком уходит в рендерер
  в каждом IPC-событии (в том числе на каждый чанк вывода), поэтому длинный прогон раздувал
  память main и рендерера линейно от длины вывода.
- Метрики были фикцией: `tokensEstimated = chars / 4`, стоимости не было. Реальный usage
  есть в `stream-json` Claude CLI (события `assistant` и `result` с `total_cost_usd`) и в
  ответах API-провайдеров, но не собирался. Бюджет из [[decision-9]] было не на что опереть.

Рассматривались варианты. Хранить сессии в одном общем JSON (просто, но одна битая запись
или гонка записи теряет всё, а файл растёт с числом прогонов). Хранить транскрипты внутри
JSON сессии (удобно, но заставляет переписывать мегабайты на каждый чанк). Считать стоимость
только по данным провайдера (точно, но для API-движков и сторонних CLI её никто не сообщает).
Оценивать токены по символам (как было; расходится с реальностью в разы из-за кэша и
инструментов).

## Decision

1. **Файл на сессию и файл на транскрипт агента.** `SwarmSessionStore` пишет
   `<userData>/swarms/<sessionId>.json` (атомарно через tmp + rename, с полем `version` и
   миграцией при чтении) и дописывает `<userData>/swarms/<sessionId>/<agentId>.log`
   (очередь на файл, ротация в `.1.log` при 5 МБ). Запись состояния троттлится: не чаще
   раза в секунду при потоке чанков, немедленно при терминальных событиях и при выходе.
   Тяжёлые поля (потоковый вывод, дифф, вывод этапов) усекаются по `SWARM_STORAGE_LIMITS`,
   ключи API провайдеров в файл не попадают. Это тот же подход, что у `aiSessionStore`
   для AI Studio, и он соответствует [[decision-7]] (local-first, персистентность с
   дебаунсом и лимитами).
2. **Восстановление при старте.** Сервис флота загружает сессии до первого `swarm:list`.
   Незавершённые сессии и агенты помечаются `interrupted`; их worktree сверяются с
   `git worktree list` и файловой системой, потерянные получают `worktreeMissing`.
   Пользователь выбирает: возобновить (агент перезапускается в том же worktree с промптом
   «продолжи с места остановки», handoff продолжается с незавершённого этапа) или закрыть
   с очисткой (материализация по [[decision-8]], удаление worktree, веток `swarm/*`
   и `handoff/*`, файлов состояния и транскриптов). При штатном выходе активные сессии
   помечаются `interrupted` до завершения процессов.
3. **Кольцевые буферы в памяти, полный текст в файле.** `logs` ограничен 400 строками и
   256 КБ, `liveOutput` хранит хвост в 200 тысяч символов; вытеснение считается
   (`logsDropped`, `liveOutputTruncated`) и показывается в UI. Полный транскрипт открывается
   из арены по запросу через `swarm:readTranscript` (хвост до 2 МБ). Память main и
   рендерера не растёт линейно от длины прогона.
4. **Реальный usage и стоимость с явным источником.** Claude CLI запускается в режиме
   `-p --output-format stream-json --verbose`, промпт передаётся через stdin (без
   экранирования аргументов оболочки). События `assistant` дают usage по ходам, событие
   `result` даёт итоговые токены, `total_cost_usd` и модель из `modelUsage`. API-движок
   читает `usage` из стрима (Anthropic `message_start`/`message_delta`, OpenAI-совместимые
   провайдеры через `stream_options.include_usage`, OpenRouter дополнительно сообщает
   `cost`). Для Codex/Aider итоговые строки парсятся best-effort. Стоимость считается по
   таблице цен (`agentCost.ts`, USD за 1M токенов по четырём категориям: вход, выход,
   чтение и запись кэша) с датой актуальности; пользователь переопределяет цены в
   `<userData>/agent-pricing.json`. У каждого значения есть `costSource`:
   `provider`, `price-table` или `unknown` (модель не найдена, стоимость не показывается).
   Тот же парсер `result` даёт usage сообщениям AI Studio.
5. **Бюджет на слот и на сессию.** `budgetUsd` в `AgentSlotConfig` (будущая роль по
   [[decision-9]]) и в опциях запуска сессии. Проверка выполняется при каждом обновлении
   usage: превышение бюджета слота убивает процесс агента и ставит статус
   `budget_exceeded` с текстом причины; превышение бюджета сессии останавливает всех
   активных агентов, сессия завершается со статусом `failed` и понятной ошибкой.
   Для Claude CLI проверка срабатывает по ходам (usage приходит в каждом `assistant`),
   для однократных API-ответов после ответа.
6. **Экспорт сессии.** Markdown-отчёт (сводка, таблица агентов с токенами, стоимостью,
   диффом и коммитом, вывод и дифф каждого агента) и JSON (без хвостов логов и ключей) для
   вложения в задачу Backlog.md или описание PR; сохранение через системный диалог.

## Consequences

- Плюс: сессии и результаты переживают перезапуск, осиротевших worktree после краша
  больше нет: у каждого есть сессия с кнопками «возобновить» и «закрыть».
- Плюс: стоимость видна по каждому агенту и по сессии, бюджет реально останавливает
  агента, а не только показывается.
- Плюс: память ограничена константами, а не длиной прогона.
- Минус: таблица цен встроена в код и устаревает; дата актуальности показывается, но
  обновление требует релиза или ручного `agent-pricing.json`. Автообновление цен из сети
  противоречит [[decision-7]] и не планируется.
- Минус: для сторонних CLI usage best-effort, а для API-движка бюджет срабатывает только
  после ответа (единственный запрос на агента). Многоходовой API-агент появится вместе
  с ролями (TASK-60) и унаследует проверку по ходам.
- Долг: `aiSessionStore` всё ещё пишет в `~/.projecthub/sessions`, а swarm в
  `<userData>/swarms`; унификация путей в TASK-59. Автосудья (TASK-61) использует
  стоимость и время из этого решения как входы скоринга ([[decision-12]]).
- Реализация: TASK-56.
