## Context

ProjectHub — local-first harness ([[decision-7]]), и его ценность в том, что он работает с любым
агентным движком и любой моделью, которую выбрал пользователь: Claude Code CLI как основной движок
([[decision-4]]), API-провайдеры как дополнение, локальные модели через Ollama для приватности.
Владелец проекта явно зафиксировал требование (2026-09-15): **ProjectHub обязан одинаково хорошо
работать с любой LLM, а не с конкретным флагманом; GPT-6 Astra не является ни целью, ни
предпочтением.**

Сентябрь 2026 показал, как быстро меняется рынок моделей и протоколов, и где ProjectHub
привязан к конкретным именам:

- OpenAI выпустила GPT-6 Astra (`gpt-6-astra`) и линейку GPT-5.6 (`sol`, `terra`, `luna`), сняв
  `gpt-5.4`/`gpt-5.4-mini`. Из этого релиза для harness важны не сами модели, а тенденции
  (см. doc-10): рабочий computer use, «context notes» вместо сжатия контекста, деградировавшая
  наблюдаемость цепочки рассуждений и рекомендация самого вендора полагаться на HITL-гейты и
  аудит, а не на транскрипты. Astra при этом — лишь одна строка в каталоге моделей.
- `aiAgentService` знает пять провайдеров (`anthropic`, `openrouter`, `deepseek`, `ollama`,
  `custom`). `custom` — голый эндпоинт без каталога моделей, флагов возможностей, параметра
  усилия рассуждений и стоимости; любой новый сервис (Mistral, Groq, xAI, LM Studio, vLLM,
  llama.cpp) приходится «притворять» custom-ом. Таблица цен `agentCost` — встроенная, хотя
  файл переопределения `<userData>/agent-pricing.json` уже поддерживается.
- Движок `codex-cli` запускается как `codex exec --json` (TASK-60): нет HITL (только
  `--ask-for-approval on-failure|never`), `ENGINE_CAPABILITIES` для него — `tools: false,
  maxTurns: false`, нет resume и выбора усилия, схема JSONL «не документирована». С 2026 года
  все поверхности Codex работают через **`codex app-server`** — долгоживущий процесс с
  двунаправленным JSON-RPC 2.0: `thread/start|resume|fork`, `turn/start|steer|interrupt`,
  события `item/*`, серверные запросы `execCommandApproval`/`applyPatchApproval`, `model/list`
  с `supportedReasoningEfforts`, хуки и субагенты. Важно: app-server работает с любым
  `model_provider` из `config.toml`, включая локальные OpenAI-совместимые серверы, то есть это
  движок, а не привязка к OpenAI.
- Роли ([[decision-9]]) и слоты хранят конкретные `model`-id. При смене поколения (ретайр 5.4,
  выход Claude 5, Astra) роли молча ломаются, а выбор «дёшево / сбалансированно / фронтир»
  делается руками для каждого движка.

Рассмотренные и отвергнутые альтернативы: нативный провайдер только для OpenAI (закрепляет
вендора — противоречит требованию); подключать новые модели только через OpenRouter (посредник,
нет локальных моделей, нет полного набора параметров); оставить `codex exec --json` (нет HITL —
нарушает [[decision-10]]); OpenAI Agents SDK как рантайм (Python, вендорский).

## Decision

0. **Принцип: ProjectHub не привязан к вендору LLM.** Ни одна функция harness (Done-loop,
   Automations, память, чекпоинты, планировщик, роли, HITL) не может требовать конкретную модель
   или конкретного провайдера. Любая модель — облачная или локальная — равноправна; дефолты
   выбирает пользователь, «из коробки» ничего не навязывается. Упоминания конкретных моделей в
   документации и коде — справочные примеры, не требования.
1. **Провайдер `custom` обобщается в «OpenAI-совместимый провайдер с профилями»** (несколько
   профилей одновременно: `baseUrl`, ключ в `secretStorageService`, флаги совместимости —
   tools, усилие рассуждений, `response_format`, usage, vision). Встроенные пресеты покрывают
   OpenAI, Mistral, Groq, xAI, Together, Fireworks, DeepSeek, OpenRouter, Ollama `/v1`,
   LM Studio, vLLM, llama.cpp server, Jan. Каталог моделей — из `/v1/models` провайдера с
   кэшем; ручной ввод id сохраняется. `anthropic` остаётся отдельным адаптером (Messages API).
2. **Усилие рассуждений — универсальный параметр слота/сессии** (`none|low|medium|high|max`),
   который адаптер транслирует в формат провайдера (`reasoning_effort`, `reasoning.effort`,
   `thinking.budget_tokens`, `think`) или игнорирует, если модель не поддерживает.
3. **Цены — редактируемые данные, а не код.** Таблица `agent-pricing.json` получает UI-редактор
   и импорт из OpenRouter; локальные модели считаются по нулевой цене; встроенная таблица —
   справочник с датой актуальности.
4. **Codex подключается через `codex app-server` (JSON-RPC), а не `codex exec`.** Один
   долгоживущий процесс на проект, `thread/start` на агента, `turn/start` на промпт;
   `execCommandApproval`/`applyPatchApproval` — в общую HITL-очередь ([[decision-10]]) наравне
   с `--permission-prompt-tool` Claude; `turn/interrupt` — остановка; `thread/resume` —
   восстановление ([[decision-16]]). `ENGINE_CAPABILITIES['codex-cli']` → `tools: true`,
   `maxTurns: true`. Codex — один из движков через единый адаптер ([[decision-4]] п. 4), его
   отсутствие не ограничивает ни одну функцию harness.
5. **Роли и слоты ссылаются на тиры моделей** — `cheap | balanced | frontier` — а не на id.
   Тир резолвится в модель per-движок/провайдер из редактируемой таблицы
   (`<userData>/model-tiers.json`), которая при первом запуске заполняется из того, что реально
   настроено у пользователя (профили, Ollama, Claude CLI), без вендорских дефолтов. Локальная
   модель может быть любым тиром, включая frontier. Явный id допустим как переопределение.
6. **Fallback-цепочка**: при 429/503/недоступности модели слот переключается на следующую
   модель того же тира (или тира ниже) с записью в лог и уведомлением; существующий
   `RateLimitWarningBanner` показывает причину.
7. **Политика безопасности для автономных запусков не зависит от модели**: Automations и
   автозапуск назначенных задач выполняются только с sandbox `workspace-write` и HITL-политикой
   роли; полный auto-approve/`danger-full-access` недоступен автономным запускам. Аудит-лог HITL
   ([[decision-10]]) — источник правды вместо транскрипта, для любой модели.

## Consequences

- Плюс: любой новый сервис или локальный сервер подключается настройкой профиля, без правок кода;
  роли переживают смену поколений моделей; выбор «дёшево / фронтир» — настройка, не правка файлов.
- Плюс: Codex становится полноценным движком слота (HITL, resume, усилие, `review/start`), но
  остаётся необязательным.
- Минус: адаптер должен аккуратно обрабатывать расхождения «OpenAI-совместимых» серверов
  (usage отсутствует, `tools` частично, разные имена полей рассуждений) — нужен набор
  флагов совместимости и тесты на каждый пресет.
- Минус: JSON-RPC-клиент app-server — отдельная реализация с версионированием протокола; Codex
  не установлен и не оплачен на машине разработки, реализация по документации с ручным
  smoke-тестом (как TASK-60).
- Долг: старые пути `openrouter`/`deepseek` — частные случаи новых профилей; после миграции
  их следует свернуть в пресеты, оставив совместимость настроек.
- Реализация: TASK-70 (универсальный провайдер, каталог, цены), TASK-71 (app-server),
  TASK-79 (тиры и fallback). Статус ADR переводится в `accepted` после TASK-70 и TASK-79;
  п. 4 — после TASK-71.
