## Context

Владелец проекта (2026-09-15) требует, чтобы агент из ProjectHub мог полностью управлять
компьютером — курсором, клавиатурой, окнами — а не только браузером или файлами в worktree.
При этом действует принцип независимости от вендора LLM ([[decision-26]] п. 0): возможность
должна работать с любым движком (Claude Code, Codex app-server, Gemini CLI, API-агент) и любой
моделью, включая локальные без vision.

Что есть на рынке (исследование 2026-09-15):

- **Встроенный computer use у вендоров.** Claude Code получил управление рабочим столом
  (macOS — март 2026, Windows — апрель; технология Vercept; research preview для Pro/Max) как
  встроенную, не MCP, возможность; Anthropic API — `computer_toolset_20260801` (17 действий:
  screenshot, zoom, клики, drag, scroll, type, key, hold_key, wait), но не в Claude Code/Agent SDK
  для локальной машины; GPT-6 Astra — computer use через Codex (hosted). Всё это привязано к
  вендору и не даёт единой HITL-политики ProjectHub.
- **MCP-серверы управления рабочим столом:**
  - `@zavora-ai/computer-use-mcp` — MIT, Rust NAPI, npm, Windows x64/arm64, macOS, Linux; ~70
    инструментов: скриншот и zoom, мышь, клавиатура, буфер, окна/фокус, дерево доступности,
    скриптинг (PowerShell/AppleScript), профили `core`/`ax`/`full`; stdio; v7.4, активен.
  - `CursorTouch/Windows-MCP` — MIT, Python 3.13, 7k★; UIA-дерево, «работает с любой LLM без
    vision», DOM-режим для браузеров, задержка 0,2–0,5 с; только Windows, тянет Python.
  - `sbroenne/mcp-windows` — MIT, .NET 10; семантический UIA по именам элементов, JPEG и
    auto-diff (−84–96 % токенов); только Windows, .NET-рантайм.
- **Библиотеки для собственной реализации**: nut.js (upstream перешёл на платную модель, есть
  MIT-форк `@nut-tree-fork/nut-js`, обновляется редко), robotjs (не поддерживается). Писать
  собственный рантайм поверх них — изобретать то, что уже есть в MIT-серверах.

Что уже есть в ProjectHub и что нужно переиспользовать: встроенный HTTP/SSE MCP-сервер
(`mcpServerService`, TASK-19/29) с аутентификацией, единый HITL-контур с очередью запросов,
политиками ролей и аудит-логом ([[decision-10]]), `notificationService`/трей, оверлеи по
[[decision-17]], трасса и чекпоинты (TASK-72).

Отвергнутые альтернативы: подключать `computer-use-mcp` напрямую в `.mcp.json` каждого
движка (HITL зависел бы от системы разрешений движка: у Claude есть `--permission-prompt-tool`,
у Codex — approvals, у API-агента — ничего; аудит и kill-switch пришлось бы делать трижды);
делать основой встроенный computer use Claude Code (вендорская привязка, нет на других
движках); собственная реализация на nut.js (см. выше).

## Decision

1. **Рантайм — `@zavora-ai/computer-use-mcp`** (MIT, Node-native, кроссплатформенный, есть
   дерево доступности). Запасной вариант для Windows при слабом a11y-дереве —
   `Windows-MCP` (Python) как опциональный профиль по флагу, как LightRAG.
2. **Единая точка входа — MCP-прокси ProjectHub.** `mcpServerService` спавнит рантайм как
   дочерний stdio-процесс и ре-экспортирует его инструменты под префиксом `computer_*`. Агенты
   всех движков подключаются к ProjectHub, а не к рантайму напрямую, поэтому политика, аудит,
   лимиты и kill-switch одинаковы для всех и не зависят от возможностей движка.
3. **HITL по классам действий.** Каждый инструмент классифицируется: `observe` (скриншот,
   дерево, список окон, позиция курсора) — автоматически; `act` (клик, ввод, скролл, фокус,
   буфер) — автоматически только в allowlist приложений/окон роли или проекта, иначе запрос;
   `dangerous` (скриптинг PowerShell/AppleScript, файловые диалоги, действия вне allowlist,
   удержание клавиш) — всегда запрос. Классификация — данные (таблица), а не ветвления в коде.
4. **Kill-switch и видимость.** Глобальная горячая клавиша и перехват мыши человеком мгновенно
   останавливают сессию и блокируют прокси до ручного снятия; пока агент управляет компьютером,
   поверх всех окон виден оверлей с кнопкой Стоп. Каждое `act`/`dangerous` действие пишется в
   аудит-лог со скриншотами «до/после» и попадает в трассу сессии.
5. **Accessibility-first.** Системный промпт предписывает сначала читать дерево доступности и
   действовать по элементам, а скриншот использовать для проверки результата. Так возможность
   работает с моделями без vision и экономит токены; скриншоты масштабируются прокси, координаты
   пересчитываются обратно.
6. **Границы автономности.** Управление компьютером недоступно в Automations (TASK-74) и в
   автозапуске назначенных задач; в Done-loop — только если задача явно это разрешает; фича
   шаблона `computerUse` по умолчанию выключена.
7. **Вендорские возможности — как дополнение.** Встроенный computer use Claude Code и
   `computer_toolset` Anthropic API могут подключаться параллельно, но не являются основой и не
   освобождают от политики п. 3–4 там, где ProjectHub может её применить.

## Consequences

- Плюс: одна реализация HITL/аудита/kill-switch для всех движков и моделей; локальные модели без
  vision управляют компьютером через дерево доступности; голосовое управление компьютером и
  системная диктовка (TASK-83) строятся поверх тех же инструментов.
- Плюс: рантайм — внешний MIT-пакет, ProjectHub не сопровождает нативный код для трёх ОС.
- Минус: зависимость от внешнего проекта с быстрым релизным циклом — фиксировать версию,
  проверять набор инструментов при старте, деградировать без краша.
- Минус: прокси добавляет задержку на каждое действие (IPC + HITL) — для `observe` она
  минимальна, для `act` в allowlist — доли секунды; за пределами allowlist задержка равна времени
  реакции человека, и это осознанно.
- Риск: агент с управлением компьютером — самый опасный инструмент в системе; поэтому allowlist,
  kill-switch и запрет автономных запусков — не настройки «по желанию», а часть контракта.
- Реализация: TASK-82 (прокси, политика, kill-switch, фича шаблона), TASK-83 (голос).
  Статус переводится в `accepted` после TASK-82 и проверки сценария в собранном приложении.

## Реализация и уточнения (TASK-82, 2026-09-15)

Решение принято и реализовано; в ходе задачи уточнено:

1. **Рантайм проверен на практике** (Windows 10, `@zavora-ai/computer-use-mcp@7.4.0`, версия
   зафиксирована): 70 инструментов, из них прокси экспортирует 61. Не экспортируются
   `openai_computer` (пакет действий обходит поштучную политику), `get_tool_guide` (советует
   скриптинг раньше дерева доступности), `doctor`/`policy_status` (только в настройках),
   `browser_*`/`scrape`/`web_search` (браузер — TASK-78). Неизвестные новые инструменты не
   экспортируются, пока их не классифицируют в `computerToolCatalog.ts` (fail-closed).
2. **Дерево доступности:** у нативных окон (Win32/WPF) полное; у Chromium/Electron (VS Code,
   Chrome, Obsidian) — только каркас, Chromium не включает accessibility без скринридера. Для
   таких окон остаются скриншот и координаты.
3. **Ограничение рантайма:** на Windows `open_application` лишь активирует уже запущенное
   приложение и всегда отвечает «Opened … (activated: false)». Прокси сам запускает приложение
   по голому имени `*.exe` (без пути и аргументов, `isLaunchableAppName`) — только после того, как
   действие прошло политику/HITL, — и ждёт его окно до 8 с, возвращая модели `window_id`.
4. **Цель действия для allowlist** определяется по `list_windows`: окно из аргументов →
   приложение → окно по заголовку → верхнее окно под точкой → активное окно. Действия в окнах с
   заголовком файлового диалога («Save As», «Сохранить как»…) повышаются до `dangerous`.
5. **Координаты:** по умолчанию `coordinate_space: "screen"` (как у рантайма и `bounds` дерева
   доступности); пересчёт со скриншота — только при явном `"screenshot"`. Формула пересчёта
   рантайма в ответе заменяется текстом прокси: иначе vision-модель, умножившая координаты сама,
   получала бы двойной пересчёт. Скриншоты вписываются в 1366×768, JPEG 70.
6. **Allowlist сужает только роль** (`permissions.autoApprove === false`), а не глобальный
   переключатель auto-approve команд AI Studio — иначе allowlist не работал бы у большинства
   пользователей.
7. **Kill-switch:** `Control+Alt+Escape`, кнопка «Стоп» в окне-оверлее и баннере, перехват мыши
   (> 40 px за 200 мс) — только во время действия агента и 3 с после, чтобы человек мог нажать
   «Разрешить» в карточке. Срабатывание убивает процесс рантайма (прерывая текущее действие),
   отменяет ожидающие `computer_action`, прерывает сессии AI Studio и блокирует прокси до ручного
   снятия.
8. **Аудит:** решения `computer_action` в едином HITL-логе; скриншоты «до/после» —
   `<userData>/audit/computer/<yyyy-mm>/`. Observe-вызовы в аудит не пишутся (иначе лог
   заполнялся бы скриншотами).
9. **Внешние агенты** подключаются фичей шаблона `computerUse` через stdio-мост
   `scripts/computer-use/computer-use-bridge.mjs`; токен — только в `PROJECTHUB_MCP_TOKEN`, в
   коммитящиеся `.mcp.json`/`.agents/mcp_config.json` не пишется. Origin таких сессий — `external`.
10. **API-агент** получил многошаговый tool-loop (результаты инструментов возвращаются модели) и
    tool calling для OpenAI-совместимых провайдеров; изображения в результатах инструментов у них
    не передаются до флагов возможностей моделей (TASK-70).
11. **Claude CLI и многострочный промпт:** CLI запускается через оболочку, cmd.exe обрезает
    командную строку на переводе строки, поэтому инструкции передаются файлом
    `--append-system-prompt-file` (AI Studio и Swarm/Done-loop).

12. **Детектор перехвата мыши и автоматизация интерфейса несовместимы.** Клики автоматизации
    (Playwright и т. п.) двигают системный курсор, и детектор — правильно — считает их перехватом
    со стороны человека: прогон обрывается на первой же карточке, которую пытаются одобрить кликом.
    Поэтому проверки, где карточки одобряются автоматизацией, идут либо с одобрением через MCP
    (`projecthub_approve_action`), либо с временно выключенным `takeoverDetection`. Для человека это
    не ограничение: он одобряет карточку в паузе между действиями агента, когда детектор не армирован.

Проверено сценарием «открыть Блокнот, напечатать текст, сохранить файл»: **пройден** Claude Code в
терминале через мост, Claude CLI внутри AI Studio и Claude CLI в **собранном приложении**
(`release/win-unpacked/ProjectHub.exe`, 2026-09-16: 12 действий, дерево доступности, действия в
Блокноте — авто по allowlist, в «Save As» — через карточки HITL); **не пройден** API-агент на
локальной `qwen2.5:7b-instruct` — модель не следует инструкции: вызывает несуществующие цели
(`com.example.myapp`) и батч-инструмент `multi_edit` вместо названных инструментов, упирается в лимит
шагов. Прокси при этом отрабатывает верно: каждый такой вызов уходит в HITL и отклоняется.

**Kill-switch проверен реальным вводом** (2026-09-16, изолированный экземпляр): синтетическое нажатие
`Ctrl+Alt+Esc` отдельным процессом рантайма (`KILL-SWITCH (hotkey)`) и резкие движения курсора во
время действия агента (`KILL-SWITCH (human-takeover)`) блокируют прокси — после срабатывания и
`observe`, и `act` отвечают отказом до ручного снятия, приложение остаётся живым. Электронный
`globalShortcut` срабатывает и на синтетический ввод, а не только на физический.

**Недоступный рантайм** (экземпляр без `npx` в PATH): приложение работает, модалка показывает
причину — «Не найден npx (нужен Node.js ≥ 20 в PATH)» вместе со stderr рантайма; диагностика и
тестовый скриншот возвращают ту же ошибку и не роняют приложение. Обёртка сообщения переведена
(ru/en), сам текст ошибки main-процесса — русский, как и в остальных сервисах.

Порядок работы: сначала Claude Code, другие провайдеры — следом.
