## Context

Потоковый API-путь `aiAgentService.requestAnthropic` (провайдер `anthropic` с ключом, мимо Claude CLI)
собирал тело запроса к Messages API inline, и у этой сборки было четыре дефекта (TASK-88):

- `max_tokens: 4096` был захардкожен, и переопределить его было нечем. Длинные ответы агента молча обрезались.
- Extended thinking включался по условию `thinkingBudget > 0 && model.includes('3-7')`, то есть только
  для снятого с обслуживания `claude-3-7-sonnet`. Слайдер в `AISettingsModal` показывался по той же подстроке.
- `temperature` жила в ветке `else` от thinking и подставлялась со значением по умолчанию 0.7, даже когда
  пользователь её не задавал.
- В `getConfig()`, в теле запроса, в `agentFleetService` (fallback API-агента роя) и в `NewSwarmModal`
  был прописан вендорский дефолт модели `claude-3-7-sonnet-*`, что противоречит [[decision-26]] п. 0.

Факты об API Anthropic на сентябрь 2026 (документация platform.claude.com: Extended thinking,
Troubleshooting thinking, Thinking → Sampling parameters, Models API):

- Режимы thinking зависят от модели. У Fable/Mythos 5.x, Opus 5, Opus 4.8/4.7 и Sonnet 5 есть только
  `{type: "adaptive"}`, а `{type: "enabled", budget_tokens}` даёт 400. У Opus 4.6 и Sonnet 4.6 доступны оба
  режима, но `enabled` устарел. У Claude 4.5 (Opus/Sonnet/Haiku) и более ранних Claude 4 есть только
  `enabled`, а `adaptive` даёт 400. `budget_tokens` должен быть не меньше 1024 и меньше `max_tokens`.
- `GET /v1/models/{id}` возвращает `capabilities.thinking.types.adaptive|enabled.supported` и
  `max_tokens` — явный, машиночитаемый признак возможностей. Признака «принимает sampling-параметры»
  в ответе нет.
- На Fable/Mythos 5.x, Mythos Preview, Opus 5, Opus 4.8/4.7 и Sonnet 5 нестандартная `temperature`
  (а также `top_p`/`top_k`) даёт 400 в любом запросе. На более старых моделях `temperature` несовместима
  с включённым thinking.

Из последнего следует, что AC#3 TASK-88 в буквальной формулировке («можно задать температуру независимо от
режима рассуждений») невыполним: это ограничение самого API. Владелец проекта согласовал сужение
AC#3 до «честной развязки» (2026-09-17).

Рассмотренные и отвергнутые альтернативы:

- **Статическая таблица семейств моделей для thinking.** Её пришлось бы обновлять с каждым поколением
  моделей — это та же привязка к именам, только в другом месте.
- **Спрашивать режим thinking у пользователя.** Ошибка в настройке превращается в 400, а знание уже
  есть в Models API.
- **Возвращать ошибку, если заданы и temperature, и thinking.** Сохранённая в старых конфигах
  `temperature: 0.7` сломала бы запросы ко всем актуальным моделям.
- **Реактивно повторять запрос без параметра после 400.** Это лишний платный запрос и разбор текста
  ошибки вместо типизированного признака.

## Decision

1. **Сборка тела запроса — чистая функция** `buildAnthropicMessagesBody(input, capabilities)` в
   `electron/services/anthropicRequest.ts`, без Electron и сети, покрыта unit-тестами
   (`tests/unit/anthropicRequest.test.ts`). Функция возвращает тело и `notes` — пояснения, какие
   настройки не попали в запрос и почему. `aiAgentService` пишет их в лог на уровне info один раз за ход.
2. **Модель обязательна.** Пустая строка и `default` (сентинел Claude CLI) означают «модель не
   выбрана»: API-путь и `complete()` возвращают понятную ошибку. `getConfig()` без файла настроек
   отдаёт `{ provider: 'anthropic', model: 'default' }` без `temperature` и `thinkingBudget`. API-агент роя
   без `providerConfig` берёт настройки AI Studio пользователя. В шаблонах `NewSwarmModal` модель —
   `default`.
3. **Возможности модели — из Models API** (`GET /v1/models/{id}`), один запрос на модель за время жизни
   процесса. Успешный ответ кэшируется в памяти main-процесса, ошибка — на 60 секунд. Если запрос
   не удался, основной запрос к модели всё равно выполняется, но без `thinking`, а в лог пишется
   предупреждение.
4. **Режим thinking** включается при `thinkingBudget > 0`:
   - если модель поддерживает `adaptive`, уходит `{type: "adaptive", display: "summarized"}`, бюджет не
     используется. Режим `adaptive` предпочтительнее, даже если доступен и `enabled`. `summarized` нужен,
     потому что на новых моделях по умолчанию текст рассуждений не возвращается, а AI Studio его показывает;
   - если модель поддерживает только `enabled`, уходит `{type: "enabled", budget_tokens}`, где бюджет
     не меньше 1024 и строго меньше `max_tokens`. Если места под бюджет нет, thinking не отправляется;
   - если модель рассуждения не поддерживает или её возможности неизвестны, thinking не отправляется.
   `thinkingBudget = 0` (или не задан) означает «режим модели по умолчанию», а не «выключено»: на
   Opus 5 и Sonnet 5 рассуждения включены по умолчанию, на Fable и Mythos их нельзя выключить.
5. **`max_tokens`** задаёт вызывающий код через `AIStreamRequest.maxTokens` (поле добавлено и в копию
   типов рендерера). По умолчанию — 64 000, потолок потокового пути по рекомендации Anthropic для
   стрима. Значение ограничивается `max_tokens` модели из Models API.
6. **`temperature` отправляется только при выполнении всех условий**: её явно задали; модель входит в
   закрытый allow-список семейств, выпущенных до отказа от sampling-параметров (`claude-3*`,
   `claude-(opus|sonnet|haiku)-4`, `-4-0` … `-4-6`, с датой или `-latest`); thinking в этом запросе не
   отправлен. В остальных случаях параметр отбрасывается с пояснением в `notes`. Список закрыт
   сознательно: новые модели в него не попадут, а неизвестная модель безопасно получает запрос без
   `temperature` — отсутствие параметра API принимает всегда. Дефолт 0.7 убран из `getConfig()` и из
   `DEFAULT_CONFIG` рендерера; в настройках появились состояние «по умолчанию модели» и кнопка сброса.
7. **Каталог подсказок `MODEL_PRESETS`** в `AISettingsModal` очищен от снятых `claude-3-*` и дополнен
   актуальными идентификаторами (`claude-fable-5-1`, `claude-opus-5`, `claude-sonnet-5`,
   `claude-haiku-4-5`) — как справочные подсказки поля, без выбора по умолчанию (согласовано с
   владельцем 2026-09-17). Слайдер Thinking Budget показывается для провайдера `anthropic` без условия на
   имя модели.

## Consequences

- Плюс: рассуждения работают на любой модели, для которой Models API публикует признак, включая
  будущие, без правок кода. Длинные ответы агента больше не обрезаются на 4096 токенах. Сохранённая
  `temperature` больше не ломает запросы к Opus 4.7+, Sonnet 5 и Fable ответом 400.
- Плюс: логика тела запроса проверяется unit-тестами без сети, а причины отброшенных настроек видны
  в `main.log`.
- Минус: на каждую новую модель — один дополнительный `GET /v1/models/{id}` за сессию приложения.
  Алиасы Claude CLI (`sonnet`, `opus`) Models API не распознаёт: для API-пути нужен полный id.
- Минус: признак sampling-параметров — по имени модели (allow-список), потому что Models API его не
  публикует. Список закрытый и со временем только устаревает в безопасную сторону.
- Минус: если Models API недоступен, `max_tokens` по умолчанию (64 000) может превысить потолок старой
  модели с меньшим лимитом вывода — тогда API вернёт понятную ошибку 400.
- Долг: `thinkingBudget` как «бюджет токенов» — устаревшая абстракция. Универсальное усилие рассуждений
  (`none|low|medium|high|max` → `output_config.effort`) и явный выбор «выключить рассуждения» относятся к
  [[decision-26]] п. 2 (TASK-70).
- Долг: живая проверка на актуальной модели не выполнена — на машине разработки нет API-ключа (TASK-91).
  В OpenAI-совместимом пути остаются вендорский fallback модели и `temperature ?? 0.7` (TASK-92).
- Реализация: TASK-88.
