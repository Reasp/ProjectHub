## Context

[[decision-31]] п. 8 ввёл одноразовый вызов модели `aiAgentService.complete()` для разбора
голосовых команд и намеренно **не пускал его через Claude CLI**: основная точка входа к моделям
(`claudeBridgeService.runAgentTask`) при `provider: anthropic` без ключа запускает полноценную
агентскую CLI-сессию, а это секунды задержки. Без ключа `complete()` возвращал ошибку «модель
недоступна».

Живая проверка TASK-83 2026-09-17 показала, что это закрывает функцию для типичного пользователя:
у владельца AI Studio настроен `anthropic/sonnet` **без API-ключа** — вход в Claude Code выполнен
по подписке, и других моделей нет. Разбор свободных команд (AC#2) и голосовое управление
компьютером (AC#4) были недоступны целиком. Временное переключение на Ollama (qwen2.5) владелец
отклонил: решение должно работать на той конфигурации, которая у пользователя есть.

Замеры одноразового запроса `claude -p` на машине владельца (2026-09-17):

| Запуск | Время ответа |
|---|---|
| `claude -p` с настройками по умолчанию (MCP-серверы, инструменты, сессия, навыки) | ~8.2 с |
| `sonnet` с облегчёнными флагами (см. п. 2) | ~2.8 с |
| `haiku` с теми же флагами | ~9 с (медленнее sonnet, поэтому «быстрая» модель не выбирается автоматически) |

Рассмотренные альтернативы:

- **Оставить ошибку и требовать API-ключ** — функция недоступна пользователю подписки, а
  [[decision-26]] п. 0 требует равноправия способов доступа, а не только вендоров.
- **Ходить через `claudeBridgeService.runAgentTask`** для классификации — ~8 с на команду,
  агентский цикл, сессия на диске и системный промпт Claude Code, который мешает строгому формату
  ответа.
- **Подставлять локальную модель по умолчанию** — запрещено [[decision-26]] п. 0 (никаких
  дефолтных моделей).

## Decision

1. **`complete()` для `provider: anthropic` без API-ключа идёт в Claude Code CLI по подписке**
   (`completeClaudeCli`). С ключом — Messages API, как раньше; остальные провайдеры — OpenAI-
   совместимый путь. Пересматривает ограничение [[decision-31]] п. 8 «не ходить через Claude CLI»;
   остальной контракт [[decision-31]] (JSON-объект, запасной голый интент, каталог, порог) не
   меняется.
2. **Запуск максимально облегчён**, команда собирается чистым модулем `claudeCliCompletion`
   (unit-тесты): `-p --model <модель из настроек> --output-format json --strict-mcp-config --tools=
   --no-session-persistence --disable-slash-commands --system-prompt <короткий служебный промпт>`.
   Инструкции и запрос передаются через stdin; рабочий каталог — временный, чтобы CLI не подтягивал
   `CLAUDE.md` проекта; `CLAUDE_CONFIG_DIR` — каталог ProjectHub. Модель берётся только из настроек
   пользователя, вендорского дефолта нет.
3. **`maxTokens` и `temperature` в CLI-пути не передаются** — CLI их не принимает; для коротких
   служебных ответов это допустимо. Разбор ответа — поле `result` JSON-вывода, `is_error` → ошибка.
4. **Голос → компьютер (`voice:runComputerTask`) без ключа** идёт в `claudeBridgeService.runAgentTask`
   с `builtinTools: []` (`--tools=` — ни одного встроенного инструмента CLI) и `systemPromptAddon`
   с правилами голосовой команды. Доступны только MCP-инструменты `computer_*` прокси ProjectHub,
   поэтому HITL, allowlist, аудит и kill-switch ([[decision-27]]) действуют так же, как в API-пути;
   чтение файлов и запуск команд голосовой команде недоступны.
5. **Правила голосовой команды попадают в CLI-сессию существующим каналом TASK-82** —
   файлом `--append-system-prompt-file` вместе с инструкциями computer-use, а не аргументом
   командной строки (многострочный аргумент через `cmd.exe` обрезал бы остальные флаги).

## Consequences

**Плюсы.** Разбор свободных команд и голосовое управление компьютером работают у пользователя
подписки без API-ключа. Проверено живьём 2026-09-17: «хочу посмотреть, что сейчас в работе» →
вкладка «Задачи», «сделай что-нибудь хорошее» → голосовой переспрос; голосовая команда компьютеру
дошла через CLI-агента до `computer_open_application notepad.exe` и политики computer-use.

**Минусы.** ~3 с на разбор незнакомой фразы против долей секунды у локальной модели; каждый запрос
расходует квоту подписки. Параметры генерации (`temperature: 0`) в CLI-пути не задаются, поэтому
ответы чуть менее детерминированы — компенсирует толерантный разбор [[decision-31]]. Зависимость
от набора флагов CLI: при их переименовании в новой версии Claude Code запрос упадёт с ошибкой
(не молча) — страховка в unit-тестах сборки команды и в сообщении об ошибке со stderr.

**Долг.** При появлении тиров моделей (TASK-79) служебным запросам стоит отдавать быструю модель;
кэш [[decision-31]] п. 7 уже снижает число обращений к CLI за повторяющимися фразами.

Реализация — TASK-83 (п. 2 и 4). Связано с [[decision-26]], [[decision-27]], [[decision-31]].
