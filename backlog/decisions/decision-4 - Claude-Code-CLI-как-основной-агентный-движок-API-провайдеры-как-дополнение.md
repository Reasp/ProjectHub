## Context

В ProjectHub два независимых пути запуска агента:

- `claudeBridgeService` оборачивает `claude -p --output-format stream-json` и получает
  поток событий, дерево подагентов, статусы и запросы разрешений;
- `aiAgentService` ходит напрямую в API (Anthropic, OpenRouter, DeepSeek, Ollama, любой
  OpenAI-совместимый эндпоинт) со своим tool-loop из шести инструментов (`read_file`,
  `write_file`, `list_dir`, `run_command`, `search_rag`, `ask_question`).

Нужно зафиксировать, какой путь считается основным, чтобы новые возможности (роли, HITL,
swarm, контекст) не реализовывались дважды и не расходились по поведению.

## Decision

1. **Claude Code CLI является основным движком агента.** Причины: у него уже есть зрелый
   tool-loop, подагенты, MCP-клиент, чтение `CLAUDE.md` и `.mcp.json` проекта, механизм
   `--permission-prompt-tool`, который ProjectHub использует для Human-in-the-loop, учёт квоты
   и стоимости через `stats-cache.json`. Повторять это в собственном tool-loop нерационально.
2. **API-провайдеры остаются как дополнение** для трёх сценариев: локальные модели через
   Ollama (приватность, отсутствие сети), дешёвые модели для рутины (описания задач, коммиты,
   PR), и участие «чужих» моделей в Swarm Arena для сравнения результатов.
3. **Другие CLI-агенты (Codex CLI, Gemini CLI, Aider) подключаются как движки слота Swarm**
   через единый интерфейс «запусти агента в каталоге с промптом и роль-инструкцией».
   Обязательное требование к каждому движку: корректные аргументы вызова, поддержка
   system-prompt роли и работа внутри HITL-контура (см. [[decision-10]]).
4. Любая новая агентная функция (роль, контекст, аудит, метрики) сначала реализуется для
   Claude CLI, затем прокидывается в остальные движки через общий адаптер, а не через
   отдельные ветки `if engine === ...`.

## Consequences

- Плюс: ProjectHub не изобретает агентный рантайм и получает улучшения Claude Code бесплатно.
- Плюс: HITL и учёт стоимости работают на уровне CLI, а не на уровне отдельных запросов.
- Минус: зависимость от установленного `claude` и от формата `stream-json`. При недоступном
  CLI приложение обязано деградировать без краша (TASK-28) и подсказывать установку.
- Минус: API-путь имеет более слабый контекст (`buildSystemPrompt` в четыре строки) и не
  считает стоимость. Это принятый долг, закрываемый в TASK-64 и TASK-56.
- Аргументы вызова Codex CLI сейчас неверны (`-m` это модель, а не промпт) и молча уводят в
  fallback на OpenRouter. Исправление входит в TASK-60.
