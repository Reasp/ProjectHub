## Context

[[decision-26]] п. 5 и 6 требуют, чтобы роли и слоты ссылались на тир модели (`cheap | balanced | frontier`), а не на
id, и чтобы слот при 429, 503 и недоступной модели переключался на следующую модель. До TASK-79 было так:

- Роль хранила `model` (id), слот — `providerConfig.model`. Роль превращалась в слот копированием модели
  (`startAssignedAgent`, `NewSwarmModal`). При смене поколения моделей роль молча ломалась.
- Ошибка провайдера уже классифицирована ([[decision-43]]): слот получает `failed` и снимок `providerError` с видом,
  `retryable` и `retryAfterMs`. §8 decision-43 рекомендует правила fallback, но сам fallback не сделан.
- Провайдер слота разрешает `resolveSlotProviderConfig` ([[decision-40]]); профили и каталог `/models` —
  [[decision-39]]; признак `local` — у провайдера ([[decision-42]]).
- CLI-движки ошибки провайдера не классифицировали. Проверено вживую 2026-09-19 на Claude CLI 2.1.275:
  `claude -p --model no-such-model-xyz --output-format stream-json` отдаёт событие `assistant` с полями
  `error: "model_not_found"`, `is_api_error_message: true` и текстом «There's an issue with the selected model…»,
  затем `result` с `is_error: true`, `api_error_status: 404`, `terminal_reason: "api_error"` и кодом выхода 0.
  `agentFleetService` принимал такой ход за успешный: текст ошибки уходил в вывод агента, слот становился
  `completed`. Лимиты подписки CLI сообщает событием `rate_limit_event` (`status`, `resetsAt`, `rateLimitType`).
  401 для CLI вживую не получить: при входе через аккаунт CLI не берёт `ANTHROPIC_API_KEY` из окружения.
- TASK-79 зависел от TASK-71 (Codex через app-server) ради `model/list`. Codex не установлен и не оплачен.

Рассмотренные варианты:

1. **Дефолтная таблица тиров в коде** (Haiku/Sonnet/Opus, luna/sol/astra, как в исходном описании TASK-79).
   Отвергнуто: нарушает [[decision-26]] п. 0. Модели выбирает пользователь; таблица заполняется из того, что у него
   реально настроено.
2. **Тир только у роли, а слот хранит итоговый id.** Отвергнуто: слот сессии, сохранённый на диск, снова привязан к
   id, а fallback не знает цепочки.
3. **Fallback на любой ошибке с повтором той же модели.** Отвергнуто: при `auth`, `config` и большинстве `bad_request`
   другая модель той же настройки не поможет ([[decision-43]] §8), а повтор ради повтора тратит бюджет.
4. **Переключение после того, как агент уже вызывал инструменты.** Отвергнуто: API-агент в режиме `agent` и Claude CLI
   пишут файлы и выполняют команды. Повтор хода другой моделью повторил бы побочные эффекты.
5. **Ждать TASK-71 ради каталога Codex.** Отвергнуто: зависимость снята, см. п. 9.

## Decision

1. **Тир** — `cheap | balanced | frontier`, порядок от младшего к старшему. Тир говорит, какого класса модель нужна
   роли, а не какая именно. Локальная модель может стоять в любом тире, включая `frontier`.
2. **Таблица** `<userData>/model-tiers.json`, чистый модуль `electron/services/modelTiers.ts` (схема, нормализация,
   цепочка, решение о переключении), сервис `modelTierService.ts` (чтение, атомарная запись, первичное заполнение):

   ```json
   {
     "version": 1,
     "updatedAt": "2026-09-19T10:30:00.000Z",
     "fallbackToLowerTier": true,
     "maxSwitches": 2,
     "maxWaitMs": 30000,
     "tiers": {
       "cheap":    [{ "engine": "api", "profile": "Ollama", "model": "qwen2.5:7b-instruct", "source": "auto" }],
       "balanced": [{ "engine": "claude-cli", "model": "sonnet", "source": "auto" }],
       "frontier": [{ "engine": "api", "profile": "LAN Ollama", "model": "ornith:35b", "source": "manual" }]
     }
   }
   ```

   Запись тира — движок, модель и для `api` цель: `profile` (имя или id, как в роли, [[decision-40]] п. 2) или прежний
   `provider`. Без `profile` и `provider` — провайдер AI Studio. Порядок записей в тире — порядок цепочки. Битая
   запись пропускается, битый файл не ломает запуск: тиры считаются пустыми, UI показывает причину.
   `maxSwitches` ограничен диапазоном 0…2 (0 — fallback выключен), `maxWaitMs` — 0…120 000.
3. **Первичное заполнение** — только при отсутствии файла и по кнопке «Заполнить из настроенного» (добавляет
   недостающее, ручные записи не трогает). Источники — то, что есть у пользователя, без сети ([[decision-7]]):
   - модель AI Studio — в `balanced` (движок `api`, профиль или провайдер AI Studio);
   - Claude CLI, если `claude --version` отвечает: алиасы CLI `haiku` → `cheap`, `sonnet` → `balanced`,
     `opus` → `frontier`. Это алиасы самого CLI, которые он разрешает в текущее поколение, а не id моделей;
   - модели из кэша каталогов профилей, если размер указан в id (`7b`, `35b`): до 10B — `cheap`, 10–30B — `balanced`,
     больше 30B — `frontier`; эмбеддинг-модели пропускаются. Модели без размера в тиры не попадают, их
     распределяет пользователь.
   Все такие записи помечены `source: "auto"`.
4. **Роль и слот**: поле `modelTier` во frontmatter роли и в `AgentSlotConfig`. Явный `model` важнее тира и
   остаётся первым звеном цепочки, тир тогда даёт запасные модели. Старые роли с одним `model` работают как раньше:
   без тира нет и цепочки. Встроенные роли получают тиры: architect и reviewer — `frontier`, implementer и tester —
   `balanced`, doc-writer — `cheap`. Если в тире нет записей для движка слота, слот работает как без тира (модель
   AI Studio или модель CLI по умолчанию) и пишет это в лог.
5. **Цепочка** (`buildModelChain`): явная модель слота (если есть), затем записи тира для движка слота, затем, при
   `fallbackToLowerTier`, записи младших тиров по убыванию. Повторы (тот же движок, цель и модель) выкидываются. Для
   движка `api` запись превращается в конфиг слота через `providerConfigFromSpec` и дальше разрешается
   `resolveSlotProviderConfig` как обычно. Усилие рассуждений и температура слота переносятся на каждое звено.
6. **Правила переключения** (`decideFallback`, по [[decision-43]] §8):
   - `model_not_found` — следующее звено сразу;
   - `rate_limit` и `unavailable` с причиной `server`, `overloaded`, `timeout` — ждать `retryAfterMs` (не дольше
     `maxWaitMs`; без `retryAfterMs` — не ждать), затем следующее звено;
   - `unavailable` с причиной `refused`, `dns`, `tls`, `network` и `quota` — это отказ сервера или счёта, а не модели:
     следующее звено только с другой целью (другой профиль, провайдер или движок);
   - `bad_request/context` — следующее звено (размер окна моделей неизвестен, выбор — порядком в тире);
   - `auth`, `config`, остальные `bad_request`, `unknown` — не переключать: другая модель той же настройки не поможет;
   - не больше `maxSwitches` (≤ 2) переключений за ход агента. Когда лимит исчерпан или звенья кончились, слот падает
     с последней ошибкой и причиной «цепочка исчерпана» или «лимит переключений»;
   - переключение только до первого вызова инструмента в ходе. После вызова инструмента ошибка — это обычный
     `failed`, чтобы не повторять побочные эффекты. Уже выведенный текст упавшего звена стирается из вывода и
     остаётся в транскрипте агента;
   - ожидание прерывается остановкой агента или сессии.
7. **Где работает**: API-слоты (`runApiAgent`) и Claude CLI (`runClaudeCliAgent` перезапускается с `--model`
   следующего звена). Claude CLI классифицируется по событиям stream-json (`classifyClaudeCliError`): поле `error`
   события `assistant` (`model_not_found`, `rate_limit`, `authentication_failed`, `billing_error`, `invalid_request`,
   `server_error`, `overloaded`) и `api_error_status` события `result`. Ход с `result.is_error` и API-ошибкой больше не
   считается успешным, текст ошибки не попадает в вывод агента. `resetsAt` события `rate_limit_event` со статусом
   `rejected` даёт `retryAfterMs`. Codex CLI и Gemini CLI тир получают (`-m <модель>`), но ошибки не классифицируются и
   не переключаются: их схема событий не проверена, CLI не установлены. Ревьюер Arena и AI Studio без fallback: у
   них одна модель, выбранная пользователем явно.
8. **Отчёт**: снимок `AgentSlotState.modelRouting` — запрошенный тир, источник первой модели (`explicit`, `tier`,
   `default`), фактические движок, модель и цель, список переключений (с какой модели, на какую, вид, причина,
   статус, сколько ждали, время) и итог (`exhausted`, `limit`). Лог агента получает строку на каждое переключение,
   шина — событие `agent:modelFallback`, уведомления — новый тип `modelFallback` (по умолчанию трей, ОС, Remote
   Control). Карточка агента показывает тир и фактическую модель, при переключениях — список с причинами; экспорт
   Markdown — строки «Тир» и «Переключения модели», JSON — `modelRouting` целиком.
9. **Зависимость от TASK-71 снята.** Тиры Codex CLI задаются вручную и передаются как `-m <модель>` без проверки,
   каталога `model/list` нет до TASK-71. Каталог моделей тиров — от провайдеров: каталог профиля `/models` с кэшем и
   кнопкой обновления ([[decision-39]] п. 5) и алиасы Claude CLI. Модель тира, которой нет в кэше каталога её
   профиля, подсвечивается в настройках.
10. **UI**: вкладка «Тиры» в настройках AI Studio (таблица «тир × звенья», движок, цель, модель с подсказками каталога,
    порядок, флаги, «Заполнить из настроенного»); выбор тира в слоте `NewSwarmModal` и в редакторе ролей. Строки ru и en.

## Consequences

- Роли переживают смену поколения моделей: меняется одна строка таблицы, а не каждая роль. Выбор «дёшево или
  фронтир» становится настройкой.
- Слот не падает на первой временной ошибке, если в тире есть запасная модель. Переключение видно в логе, карточке,
  экспорте и уведомлении.
- Claude CLI с несуществующей моделью теперь честно `failed` (с видом `model_not_found`), а не `completed` с текстом
  ошибки в выводе. Это исправление, а не новое поведение по вкусу.
- Минус: размерная эвристика заполнения ошибается для моделей без размера в id и для MoE. Поэтому записи помечены
  `auto`, а модели без размера не распределяются.
- Минус: переключение после вызова инструмента не делается. Долгий ход, упавший посередине, остаётся `failed`.
- Минус: встроенные роли с тиром `frontier` на Claude CLI после заполнения запускаются с `--model opus`, а раньше
  шли с моделью CLI по умолчанию. Это видно в карточке, запись тира можно убрать.
- Долг: 429 и 503 облака вживую не воспроизвести (облачных ключей нет): правила проверены на фикстурах
  `provider-errors.json` и локальном HTTP-сервере с `Retry-After`. Codex/Gemini без классификации до TASK-71 и
  проверки CLI. Если понадобится fallback в Arena или AI Studio — отдельная задача.
- Проверено вживую 2026-09-19 настоящими сервисами: цепочка `no-such-model:1b` (Ollama 0.34, 404) → профиль на
  закрытом порту 11999 (ECONNREFUSED) → `qwen2.5:7b-instruct` дала ответ за 2 переключения; при четырёх звеньях с тремя
  неудачами слот упал с «исчерпан лимит переключений модели (2)»; `ornith:35b` на Ollama 0.31.2 (192.168.1.11) отработал
  как `frontier`; Anthropic с неверным ключом (401) не переключался; настоящий Claude CLI 2.1.275 с
  `no-such-model-xyz` перезапустил ход с `--model haiku`. 429 с `Retry-After` проверен на локальном HTTP-сервере через
  настоящий `aiAgentService` (ожидание 1 с, затем второе звено).
- Реализация: TASK-79 (подзадачи 79.1–79.5): `electron/services/modelTiers.ts`, `modelTierService.ts`,
  `providerErrors.ts` (`classifyClaudeCliError`, `parseClaudeCliErrorEvent`), `agentFleetService.ts`, `swarmExport.ts`,
  `src/lib/modelTierEditor.ts`, `ModelTiersSection.tsx`, `ModelTierSelect.tsx`; тесты `modelTiers.test.ts`,
  `modelFallback.test.ts`, `modelTierEditor.test.ts`, дополнения `roleService.test.ts`.
