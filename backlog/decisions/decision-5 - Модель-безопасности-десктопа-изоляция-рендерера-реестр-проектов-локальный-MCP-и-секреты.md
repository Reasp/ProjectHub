## Context

ProjectHub выполняет команды, пишет файлы, хранит API-ключи и поднимает сетевые интерфейсы
(встроенный MCP-сервер, Remote Control, Telegram-туннель). Аудиты doc-6 и doc-7 нашли RCE через
MCP-сервер с любой веб-страницы, path traversal в IPC и хранение ключей открытым текстом.
Задачи TASK-18, 29, 30, 32 закрыли эти дыры, но принципы нигде не были зафиксированы, и новая
подсистема Remote Control повторила часть ошибок (PIN без rate-limit, публичные эндпоинты
федерации, секрет в открытом JSON).

## Decision

Все подсистемы ProjectHub обязаны соблюдать следующие инварианты.

1. **Рендерер не доверенный.** `contextIsolation: true`, `nodeIntegration: false`, единый
   `contextBridge` с типизированным API, CSP, `setWindowOpenHandler` и фильтр `will-navigate`,
   обработчик permission-запросов. Рендерер не получает произвольные пути и команды в обход
   проверок main-процесса.
2. **Файловые операции ограничены зарегистрированными проектами.** Любой IPC, принимающий путь,
   проходит `assertRegisteredProject` и `pathGuard`/`projectPathGuard`. Запись агента вне корня
   проекта отклоняется даже при включённом auto-approve.
3. **Встроенный MCP-сервер слушает только loopback**, требует `Authorization: Bearer` с
   константным по времени сравнением, отвергает запросы с заголовком `Origin` и не-loopback `Host`.
   Внешним машинам он недоступен по определению. Для других ПК есть отдельный контур Remote
   Control с собственной аутентификацией (см. [[decision-11]]).
4. **Секреты хранятся только через Electron `safeStorage`** (`secrets.enc.json`). Токены, ключи
   E2EE, PIN сопряжения, токен Telegram-бота не должны лежать в открытых JSON. Имена секретов и
   содержимое файлов не попадают в логи.
5. **Любой сетевой интерфейс, торчащий наружу (LAN, туннель, релей), обязан иметь**: аутентификацию
   на каждом эндпоинте, rate-limit и блокировку на подбор PIN, per-device токены с отзывом,
   режим `readOnly` по умолчанию для новых устройств, и не раскрывать пути проектов и имена машин
   без токена.
6. **Агент выполняет опасные инструменты только через HITL** (см. [[decision-10]]). Флаг
   `--dangerously-skip-permissions` допустим лишь как явный, залогированный fallback при
   недоступном HITL-сервере и включённом пользователем auto-approve.
7. Поверхность безопасности (MCP-сервер, Remote Control, IPC-гарды) покрывается unit-тестами.
   Отсутствие тестов на `remoteControlService` и `mcpServerService` считается долгом (TASK-65, TASK-58).

## Consequences

- Плюс: единый список требований для ревью новых подсистем.
- Минус: часть удобств (открыть MCP для соседнего ПК, отключить PIN) намеренно невозможна;
  для этих сценариев используется федерация с ключевой парой.
- Отклонения Remote Control от пунктов 4 и 5 устранены в TASK-65: секреты (`secretKey`,
  `pairingPin`, `telegramBotToken`, приватный identity-ключ, per-device токены) переведены на
  `secretStorageService`/`safeStorage`, `/api/federation/*` требуют Bearer-токен, `/api/status`
  урезан до непубличного минимума, `/api/qr` (отдавал секрет без проверки) удалён, PIN защищён
  rate-limit и константным сравнением, CORS `*` снят. Тесты — `tests/unit/remoteControlAuth.test.ts`,
  `tests/unit/remoteRelayAuth.test.ts`.
