## Context

Проверки ProjectHub — только `lint`/`test`/`build` в рабочем каталоге ([[decision-20]], [[decision-28]]). Агент не может
посмотреть на результат в браузере или в самом Electron-приложении, а evidence в отчёте Done-loop проверяется только по
длине текста (минус из [[decision-28]]: «смысловую проверку дадут ревьюер или визуальная верификация»). doc-10 §1 п. 1
называет это половиной ценности современных моделей: TASK-82 закрыл рабочий стол ([[decision-27]]), TASK-78 — браузер и
Electron.

Факты (проверено 2026-09-27):

- **`@playwright/mcp` 0.0.82** (Microsoft, Apache-2.0, релиз 2026-09-18, зависит от `playwright` 1.64.0-alpha; стабильный
  `playwright-core` — 1.63.0). Версии 0.0.x выходят каждые 1–2 недели. stdio-сервер, `npx @playwright/mcp`.
- Живая проба (Windows 10, пакет в scratchpad, MCP SDK-клиент): 25 инструментов ядра — `browser_navigate`, `_snapshot`,
  `_take_screenshot`, `_click`, `_type`, `_fill_form`, `_evaluate`, `_file_upload`, `_run_code_unsafe`, `_tabs`, `_close` и
  др.; группы `network`/`storage`/`config` включаются только флагом `--caps`. Браузер по умолчанию — системный Chrome
  (`HeadlessChrome/153` при установленном Chrome 153), ничего не скачивается. `file:` заблокирован по умолчанию («Access to
  "file:" protocol is blocked») — страницу проекта нужно отдавать по HTTP. Снимки `.yml` и скриншоты без имени пишутся в
  `.playwright-mcp/` в корне рабочей области.
- README пакета: по умолчанию браузер **headed** и профиль **постоянный** (`%LOCALAPPDATA%\ms-playwright\mcp-{channel}-{hash}`),
  и «постоянный профиль может использовать только один экземпляр браузера — параллельные клиенты в одной рабочей области
  конфликтуют»; `--isolated` держит профиль в памяти. «Playwright MCP is not a security boundary»; `--allowed-origins` «не
  граница безопасности». `browser_run_code_unsafe` — «executes arbitrary JavaScript in the Playwright server process and is
  RCE-equivalent». Доступ к файлам ограничен корнями рабочей области, пока не задан `--allow-unrestricted-file-access`.
  `--extension` подключается к уже запущенному браузеру пользователя с его сессиями.
- Политика HITL сейчас не знает `browser_*`: любой MCP-инструмент в `evaluateToolRequest` попадает в `auto-other` (при
  включённом auto-approve) или `manual`. Значит, `browser_run_code_unsafe` при auto-approve прошёл бы без человека.
- В ProjectHub нет `requestSingleInstanceLock`; встроенный MCP-сервер при занятом порте 42042 берёт следующий. Общими у
  второго экземпляра остаются userData (автоматизации, Telegram, Remote Control) и реестр проектов, который читается из
  настоящего `app.getPath('home')` (память screenshot-projecthub-via-playwright).
- `nativeImage` Electron декодирует PNG в bitmap и кодирует обратно — сравнение кадров не требует новых зависимостей.

Рассмотренные и отвергнутые альтернативы:

1. **Playwright MCP через прокси ProjectHub, как `computer_*`** ([[decision-27]] п. 2). Прокси нужен рабочему столу, потому
   что там общий ресурс (мышь, клавиатура, окна человека), kill-switch и allowlist окон. Изолированный headless-браузер
   общего ресурса не имеет, у каждого клиента свой; прокси потребовал бы спавнить отдельный сервер на каждую сессию и
   ре-экспортировать 25+ меняющихся инструментов. Опасных инструментов немного, и их ловит общая политика (п. 3).
2. **Playwright CLI + skills** (`microsoft/playwright-cli`, README советует его кодинг-агентам ради токенов). Формат
   skills зависит от движка, а вызов CLI выглядит для политики как обычная команда `Bash`. MCP одинаково работает у Claude
   Code, Codex, Gemini и Antigravity ([[decision-26]] п. 0). CLI можно добавить позже как второй путь.
3. **Headed-браузер и постоянный профиль по умолчанию.** Окна всплывают поверх работы человека и двигают фокус; клики
   автоматизации ложно срабатывают как перехват мыши ([[decision-27]], уточнение п. 12); параллельные слоты Arena
   конфликтуют за один профиль.
4. **Артефакты в рабочем каталоге** (`test-results/` в worktree). Авто-коммит ([[decision-8]]) унесёт их в ветку агента,
   а очистка worktree — удалит; судья и отчёт сослались бы на файлы, которых нет.
5. **`pixelmatch`/`pngjs` или `toHaveScreenshot` Playwright Test для самопроверки.** Новые зависимости и соглашения
   раннера ради одного кадра; один и тот же рендерер на одной машине не требует детектора сглаживания. Проекты могут
   использовать `toHaveScreenshot` внутри своей проверки `ui-smoke` — это их выбор.
6. **Скриншоты, сделанные агентом через Playwright MCP, как evidence.** Файлы в рабочем каталоге агент контролирует сам
   и может подложить любую картинку. Evidence — только артефакты команд, которые запустил ProjectHub.
7. **LLM-ревьюер со зрением по скриншотам.** Зрение есть не у всех моделей, в том числе локальных ([[decision-26]]),
   и это дорого на каждой итерации. Скриншоты видит человек; ревьюер получает их список текстом.

## Decision

1. **Фича шаблона `playwright`, выключена по умолчанию.** `setup.mjs` добавляет или убирает запись `playwright` в
   `.mcp.json` и `.agents/mcp_config.json`:
   `npx --yes @playwright/mcp@0.0.82 --headless --isolated`. Версия закреплена и обновляется явно, как
   `@zavora-ai/computer-use-mcp` в [[decision-27]]. Не используются `--extension` (реальный браузер пользователя),
   `--allow-unrestricted-file-access`, `--caps`, `--port`. При включённой фиче `setup.mjs` дописывает `.playwright-mcp/`
   в `.gitignore` проекта, чтобы авто-коммит не забирал снимки агента. Фича не предлагается агентами без явного запроса,
   как `computerUse` и LightRAG (правила 7 и 20).

2. **Playwright MCP подключается напрямую, без прокси ProjectHub** (альтернатива 1). Рабочий стол по-прежнему доступен
   только через `computer_*` и прокси ([[decision-27]], правило 20 без изменений).

3. **Границы — классификация `browser_*` в общей политике HITL.** Каталог инструментов — данные (`browserToolCatalog`),
   а не ветвления. Инструмент распознаётся по имени `mcp__<сервер>__browser_<действие>` с любым именем сервера.
   - `page` — действие внутри изолированного браузера (навигация, снимок, скриншот, клики, ввод, формы, вкладки, `evaluate`
     в странице, консоль и сеть, группы `--caps`): `allow` без карточки, правило `browser-page`, в любом режиме, включая
     ручной и автономный запуск.
   - `host` — выход за пределы браузера: `browser_run_code_unsafe` (код в процессе сервера), `browser_file_upload` с путём
     вне рабочего каталога, `browser_navigate` на `file:`, `browser_take_screenshot` и `browser_snapshot` с `filename`
     вне рабочего каталога. Такой вызов всегда идёт к человеку (`ask`, `browser-host`), даже при auto-approve. В
     автономных запусках (`origin: automation | assigned`) — `deny`, правило `browser-host-autonomous` ([[decision-52]] п. 6).
   - Неизвестный `browser_*` (новая версия пакета) обрабатывается общей политикой, как любой MCP-инструмент.
   - Allow-список роли проверяется первым: запрет роли сильнее `browser-page`.
   Политика одна (`evaluateToolRequest` с контекстом «автономность, рабочий каталог») и применяется там, где ProjectHub
   видит вызов: агенты ProjectHub на Claude CLI (`--permission-prompt-tool`) и терминальные сессии через хуки
   [[decision-54]]. Слой хуков не меняется: скрипт, протокол ответа, fail-open и токен прежние, меняется только вердикт
   на сервере.

4. **Чек `ui-smoke`.** Новый вид проверки `kind: "ui-smoke"` в секции `checks` `.projecthub.json`:
   ```json
   { "id": "ui-smoke", "kind": "ui-smoke", "name": "UI smoke",
     "command": "npx playwright test --project smoke --output \"${artifactsDir}\"",
     "artifacts": { "from": ["test-results"], "minScreenshots": 1 } }
   ```
   - Команду выбирает проект: Playwright Test, свой скрипт, что угодно, что пишет картинки. Скрипт `ui-smoke` в
     `package.json` подхватывается дефолтами как проверка этого вида.
   - ProjectHub создаёт каталог артефактов и передаёт его команде в `PROJECTHUB_ARTIFACTS_DIR` и плейсхолдере
     `${artifactsDir}`. После завершения собираются файлы из этого каталога и из путей `artifacts.from` (относительно
     рабочего каталога и только внутри него): `.png .jpg .jpeg .webp` — скриншоты, `.zip` — trace; остальное игнорируется.
   - Код возврата 0, но скриншотов меньше `minScreenshots` (по умолчанию 1) — статус `failed` с причиной «нет
     скриншотов»: пустой прогон не выдаётся за визуальную проверку.
   - Сводка Playwright Test (`N passed`, `N failed`, `N flaky`) разбирается в счётчики тестов.

5. **Хранение артефактов — `<userData>/visual/`, не worktree** ([[decision-7]] п. 2, альтернатива 4).
   - Путь: `<userData>/visual/<scope>/<agentId>/<run>/<checkId>/`, где `scope` — `swarm-<sessionId>` или `adhoc`
     (автоматизации и проверки Stop-хука), `run` — `judge-<время>` или `iter-<N>`.
   - Лимиты: файл до 15 МБ, на одну проверку до 40 файлов и 60 МБ; сверх лимита файлы не копируются, результат
     помечается `artifactsTruncated`.
   - Ротация: всё хранилище до 1 ГБ и 30 дней. Чистая функция планирует удаление самых старых `scope` целиком,
     текущий не трогает. При удалении swarm-сессии её каталог удаляется.
   - Результат проверки получает `artifacts: [{ name, relPath, kind, bytes }]`. Рендерер получает картинку по IPC
     `visual:readArtifact(relPath)`: main-процесс проверяет, что путь остаётся внутри `<userData>/visual`, и отдаёт data
     URL; путей файловой системы рендерер не получает.

6. **Судья и Arena.** `ui-smoke` участвует в балле как любая проверка: статус входит в компонент `checks`, по умолчанию
   блокирующая, провал запрещает рекомендацию и авто-мердж ([[decision-20]] п. 5). Число скриншотов попадает в сводку
   проверки, которую видят ревьюер, лог и экспорт. Во вкладке «Проверки» кандидата — миниатюры и просмотр в модалке
   (`createPortal`, `z-[9999]`, [[decision-17]]), для trace — «показать в папке».

7. **Скриншоты как evidence в Done-loop.**
   - Строка отчёта агента получает необязательное поле `screenshots: ["home.png"]` — имена файлов, которые создают
     проверки `ui-smoke`. Агент сам пишет тест и знает имена заранее: отчёт пишется до проверок, сверка идёт после.
   - ProjectHub сверяет каждое имя с артефактами проверок **этой итерации**: путь внутри каталога проверки, `<checkId>/<путь>`
     или однозначное имя файла. Неразрешённое имя — критерий не засчитан («скриншот … не найден среди артефактов проверок
     итерации»).
   - Критерий с меткой `[ui]` в тексте требует хотя бы одного разрешённого скриншота.
   - Разрешённый скриншот — evidence наравне с текстом: строка со скриншотом засчитывается и при тексте короче 12 символов.
   - Снимки агента через Playwright MCP evidence не являются (альтернатива 6).
   - Инструкция цикла описывает правило, если среди проверок есть `ui-smoke`. Final Summary перечисляет имена скриншотов
     по критериям, без путей userData: файл задачи коммитится. Панель Done-loop показывает миниатюры под критерием.

8. **Самопроверка ProjectHub** — `npm run selfcheck:ui` (`scripts/visual/selfcheck.mjs`, dev-зависимость `playwright-core`
   с закреплённой версией).
   - Запуск через Playwright `_electron`: по умолчанию `release/win-unpacked/ProjectHub.exe`, с `--dev` — `electron.exe .`
     поверх `vite build` (для worktree, где exe нет). `ELECTRON_RUN_AS_NODE` из окружения убирается.
   - Изоляция от запущенного ProjectHub пользователя: свой временный `--user-data-dir` (нет общих настроек, автоматизаций,
     Telegram, Remote Control); ответ `projects:list` в копии подменяется пустым списком через `app.evaluate` — кадр
     детерминирован, реальные проекты не видны и не трогаются. Процесс и порты пользователя не затрагиваются.
   - Окно приводится к 1280×800, после загрузки снимается `page.screenshot`.
   - Сравнение — чистый модуль `scripts/visual/imageDiff.mjs`: пиксель отличается, если максимум разницы по каналам больше
     `pixelTolerance` (по умолчанию 32 из 255); кадр проходит, если доля отличающихся пикселей не больше `maxDiffRatio`
     (по умолчанию 1 %); прямоугольные маски исключают изменчивые зоны; разный размер кадров — провал. PNG декодирует и
     diff-картинку кодирует `nativeImage` запущенного приложения.
   - База — `tests/visual/baseline/main-window.<platform>.png` в git. Обновляет её только человек флагом
     `--update-baseline`; без базы прогон сохраняет кандидата и завершается провалом «нет базы».
   - Кадр, база и diff пишутся в `PROJECTHUB_ARTIFACTS_DIR`, если скрипт запущен как `ui-smoke`, иначе в `.visual-output/`
     (в `.gitignore`). В проверки Arena самого ProjectHub скрипт по умолчанию не добавляется: ему нужен exe или сборка.

## Consequences

- Плюс: агент любого движка может открыть страницу проекта и снять кадр; судья и цикл «до готовности» получают
  объективный визуальный артефакт, а evidence про UI становится проверяемым файлом, а не текстом.
- Плюс: границы задаются одной политикой для агентов ProjectHub и терминальных сессий; опасных инструментов немного, и
  они перечислены данными.
- Плюс: самопроверка ProjectHub не мешает запущенному экземпляру пользователя и не требует новых runtime-зависимостей.
- Минус: вне ProjectHub (Codex и Gemini без хуков, Antigravity, хуки в fail-open) `browser_run_code_unsafe` защищает
  только система разрешений движка и изоляция флагов. Отключить инструмент флагом пакет не позволяет.
- Минус: `@playwright/mcp` 0.0.x меняется быстро; при обновлении версии нужно сверить каталог `browser_*`.
- Минус: evidence-скриншот доказывает, что проверка сняла кадр с таким именем, но не что на нём нужное; смысл остаётся за
  человеком (миниатюры в UI) или будущим ревьюером со зрением.
- Минус: база самопроверки зависит от платформы, шрифтов и масштаба экрана; на другой машине её нужно пересоздать.
- Долг: вынести скриншоты агента из `.playwright-mcp/` в артефакты сессии (как иллюстрацию, не evidence); Playwright CLI
  как второй путь; ревьюер со зрением по флагам возможностей модели (TASK-70).
- Реализация: TASK-78. Связано: [[decision-27]], [[decision-28]], [[decision-20]], [[decision-54]], [[decision-52]],
  [[decision-7]], [[decision-17]].

## Реализация и уточнения (TASK-78, 2026-09-27)

Решение реализовано. Модули: `browserToolCatalog.ts` (каталог `browser_*`, вердикт `page`/`host`), контекст
`{ autonomous, workDir }` в `evaluateToolRequest` (агенты ProjectHub и хук PreToolUse передают рабочий каталог),
`visualArtifacts.ts` (формат `ui-smoke`, отбор с лимитами, план ротации, путь чтения, разрешение ссылок на скриншоты),
`visualArtifactService.ts` (файлы `<userData>/visual`), `executeCheck` с целью артефактов (судья — `judge-<время>`,
Done-loop — `iter-N`, автоматизации и Stop-хук — `adhoc`), поле `screenshots` в отчёте и сверка в `verifyCriteria`,
IPC `visual:readArtifact`/`visual:revealArtifact`, галерея `CheckArtifactsGallery` в Arena и панели Done-loop, вид
проверки в настройках судьи, фича `playwright` в `setup.mjs`, `scripts/visual/imageDiff.mjs` и `selfcheck.mjs`.

Уточнения по ходу:

1. **Маска шапки в самопроверке.** Два прогона одной сборки расходились на 0,51 %: бейдж Usage подгружается
   асинхронно и сдвигает соседние индикаторы. По умолчанию маскируется полоса шапки справа от сайдбара
   (`320,0,960,56` при 1280×800), флаг `--no-default-masks` её снимает. С маской повторные прогоны дают 0,00 %;
   закрашенная кнопка в базе даёт 2,02 % и провал.
2. **`filename` скриншота агента.** Playwright MCP кладёт снимок с явным `filename` в корень рабочей области, а не в
   `.playwright-mcp/`. Правило 22 требует снимать без `filename` или внутри `.playwright-mcp/`.
3. **`setup.mjs` импортируется без запуска** (`main()` только при прямом вызове) — это позволило покрыть фичу
   unit-тестом и настоящим запуском в копии.
4. Playwright Test 1.63 не находит тесты в каталоге с очень длинным путём (scratchpad агента): «did not expect test()
   to be called here». В коротком пути тот же проект проходит. Это ограничение окружения, не кода ProjectHub.
5. `F:\ProjectTemplate` (отдельный репозиторий, источник файлов для скилла) отстаёт: в его `setup.mjs` нет ни
   `computerUse`, ни `playwright`. Синхронизация — отдельная задача.

Живая проверка (Windows 10, Claude Code 2.1.280, модель haiku, Chrome 153, временный проект с веб-страницей):

- `ui-smoke` через настоящий Playwright Test в цикле «до готовности»: агент поменял заголовок и добавил кнопку,
  проверка сняла `home.png` в `<userData>/visual/swarm-…/implementer/iter-1/ui-smoke/`, ProjectHub сверил ссылку
  `"screenshots": ["home.png"]` и засчитал критерий `[ui]`; задача ушла в Review, Final Summary — «скриншоты:
  ui-smoke/home.png». 1 итерация, $0.066.
- Claude Code с Playwright MCP из `.mcp.json`, созданного `setup.mjs`: `browser_navigate`, `browser_snapshot`,
  `browser_take_screenshot` — заголовок прочитан, снимок сделан ($0.045).
- Выход за браузер: `browser_run_code_unsafe` у агента ProjectHub на Claude CLI при включённом auto-approve дал карточку
  HITL («выходит за пределы браузера»), отказ человека дошёл до модели; в запуске с `origin: automation` — отказ без
  карточки. `browser_navigate` в обоих запусках прошёл без подтверждения.
- Самопроверка ProjectHub на собранном `release/win-unpacked/ProjectHub.exe` с отдельным `--user-data-dir`: база создана
  и повторный прогон совпал на 0,00 %; настоящий userData пользователя не изменился.
