## Context

Скиллы агентов лежат в двух каталогах проекта: `.claude/skills/<имя>/SKILL.md` читает Claude Code,
`.agents/skills/<имя>/SKILL.md` — Google Antigravity (у него свой каталог, `.claude/skills` он не читает).
Один и тот же скилл поэтому живёт двумя копиями, и синхронизировать их до сих пор приходилось руками — правило
infra-dev прямо говорит «скилл `init-dev-project` при правке синхронизируй вручную». На 2026-09-28 копии
`init-dev-project` в самом ProjectHub уже разошлись между собой (другая формулировка шага опроса, лишний абзац
в копии Antigravity), а копия ProjectHub отстаёт от шаблона `F:\ProjectTemplate` (нет строк про git-хуки,
`computerUse`, `.gitattributes`). Увидеть это можно было только `diff -r`.

Экспорт ролей ([[decision-54]] п. 12) вынес менеджер скиллов в отдельную задачу TASK-105: список скиллов,
расхождения копий, копирование скилла из шаблона или другого проекта.

Рассмотренные альтернативы:

- **Генерировать `.agents/skills` из `.claude/skills` с маркером, как роли** ([[decision-54]]). Не подходит:
  скиллы пишут люди и сторонние инструменты (GitNexus кладёт свои), источника истины в ProjectHub нет, а маркер
  в `SKILL.md` — лишний шум для модели. Нужен не генератор, а сравнение и явное копирование.
- **Симлинк `.agents/skills` → `.claude/skills`.** Ломается на Windows без прав на ссылки, git хранит ссылку
  как текстовый файл, а копии иногда должны различаться (формулировки под конкретный агент).
- **Пофайловое слияние при копировании** (дописывать отсутствующие файлы, не трогая лишние). Результат
  непредсказуем: в цели остаются файлы, которых нет в источнике, и «синхронизированные» копии продолжают
  различаться. Копирование заменяет каталог скилла целиком.
- **Копирование в любой каталог на диске по пути из рендерера.** Отвергнуто по модели безопасности [[decision-5]] п. 2
  (TASK-32): только зарегистрированные проекты, шаблон из настроек и личный каталог пользователя.

## Decision

1. **Модель.** Скилл — каталог с `SKILL.md` в корне `.claude/skills` (`claude`) или `.agents/skills` (`agents`).
   Идентификатор — путь каталога относительно корня: `name` или `group/name`. Вложенный скилл показывается
   с предупреждением `nested`, потому что оба агента ищут `<корень>/<имя>/SKILL.md`. Непустой каталог без
   `SKILL.md` и без вложенных скиллов показывается как скилл с проблемой `noSkillMd`. Скрытые каталоги,
   `node_modules`, `.git`, `__pycache__` и временные каталоги копирования (`.projecthub-*`) в скилл не входят.
2. **Сравнение.** Хэш файла — SHA-256; текстовые файлы (без NUL в первых 8 КБ) хэшируются без учёта CRLF/LF,
   бинарные — побайтно. Хэш скилла — по отсортированным парам «путь — хэш». Статусы записи:
   `synced` (обе копии одинаковы), `diverged`, `claudeOnly`, `agentsOnly`. Для расходящихся копий — пофайловое
   сравнение (`same`, `changed`, `onlyClaude`, `onlyAgents`) и построчный дифф `SKILL.md` в UI.
   Проблемы формата (`noName`, `noDescription`, `nameMismatch`, `badFrontmatter`) показываются, но
   копированию не мешают. Значения frontmatter приводятся к строкам (правило 16).
3. **Лимиты и ссылки.** Скилл больше 500 файлов или 20 МБ не хэшируется (`tooLarge`) и не копируется.
   Символические ссылки и junction внутри скилла не читаются и не копируются (`symlinks`), такой скилл
   копировать нельзя. При записи ни один существующий каталог на пути `<проект>/.claude|.agents/skills/<id>`
   не должен быть ссылкой — иначе запись ушла бы за пределы проекта.
4. **Копирование — замена каталога целиком и атомарно.** Копия собирается во временном каталоге рядом с целью,
   сверяется по хэшу с источником (источник изменился по ходу — отказ) и переименованием ставится на место;
   старый каталог сначала переименовывается и удаляется после успеха, при ошибке возвращается на место.
   Действие для каждого целевого корня — `create`, `overwrite` или `unchanged`. `overwrite` выполняется только
   с `overwrite: true`; в UI это подтверждение в диалоге с предупреждением, что лишние файлы удалятся.
5. **Источники импорта.** Шаблон ProjectTemplate (путь из настроек, `PROJECT_TEMPLATE_PATH` или соседний
   каталог в dev — как у мастера проектов, путь из рендерера не принимается), личные скиллы `~/.claude/skills`
   (только корень `claude`) и другие зарегистрированные проекты (путь проверяется по реестру). Если копии
   скилла в источнике различаются, в списке импорта обе строки с пометкой, из какого корня версия. Копирование
   между корнями одного проекта — тот же путь с источником «этот проект».
6. **UI.** Вид «Скиллы проекта» в менеджере ролей рядом с «Синхронизацией в проект»: вкладки «В проекте»
   (список со статусами и проблемами, файлы копий, дифф `SKILL.md`, кнопки «Скопировать в …» и
   «Заменить копию … версией …») и «Импорт» (источник, целевые корни, действие по каждому корню, кнопка
   «Импортировать»). Индикатор на кнопке — число расходящихся скиллов. Удаление скиллов в менеджер не входит.
7. **Код.** Чистая логика — `electron/services/skillCatalog.ts`, файловая система — `skillService.ts`
   (зависимости реестра, шаблона и домашнего каталога внедряются для тестов), IPC — `electron/ipc/skillsIpc.ts`
   (`skills:list`, `skills:sources`, `skills:sourceList`, `skills:copy`), построчный дифф — `src/lib/lineDiff.ts`,
   решения панели — `src/components/ai/roles/skillsView.ts`.

## Consequences

- Расхождение копий видно в UI сразу, без `diff -r`; синхронизация — одна кнопка с подтверждением.
- Скилл из шаблона или соседнего проекта ставится без ручного копирования каталогов, лишние файлы не остаются.
- Сравнение без учёта окончаний строк не показывает ложных расхождений после git autocrlf; обратная сторона —
  копия, отличающаяся только CRLF/LF, считается одинаковой и не перезаписывается.
- Каталог `.projecthub-tmp-*` может остаться после аварийного завершения ProjectHub посреди копирования;
  в списке скиллов он не показывается, удалять его руками.
- Долг: личные скиллы Antigravity и удаление скиллов не поддерживаются; копирование в другой проект («вытолкнуть»)
  делается из того проекта через импорт.
- Реализация — TASK-105. Связано с [[decision-54]] (экспорт ролей) и [[decision-5]] (модель безопасности, пути только зарегистрированных проектов).
