## Context

Вкладка «Документация» показывала 77 документов (67 решений и 10 документов) одним плоским списком по алфавиту названий. Ссылки `[[decision-N]]`, которых в решениях 449, `MarkdownViewer` выводил сырым текстом со скобками: разбор строки знал только `` `код` ``, `**жирный**`, `*курсив*` и `[текст](url)`. Относительные ссылки на файлы не открывались вовсе (TASK-30).

Чтобы выбрать, чем задавать структуру, поведение Backlog.md CLI 1.53.0 проверено на временном проекте (2026-10-01):

- **Документы во вложенных папках поддержаны.** `backlog doc list` видит `backlog/docs/guides/doc-2 - ….md`, `backlog doc create -p guides/rag` и `backlog doc update doc-N -p guides` создают и переносят документ.
- **Решения во вложенных папках не поддержаны.** При файле `backlog/decisions/agents/decision-1 - ….md` команда `backlog decision create` выдала новому решению тот же номер `decision-1`. Раскладывать решения по папкам нельзя: нумерация ломается.
- **Неизвестные поля frontmatter документа стираются.** `backlog doc update doc-1 --title …` переписал frontmatter и удалил поле `section`. Для решений команды обновления у CLI и MCP нет, их frontmatter Backlog.md не переписывает.

Рассмотренные варианты структуры:

1. **Только вложенные папки.** Для решений не работает (см. выше). Для документов означает перенос десяти файлов, на пути к которым (`backlog/docs/doc-7 - …`) ссылаются полтора десятка задач.
2. **Отдельный файл-индекс** (`id → раздел`) в `backlog/` или `.projecthub.json`. Переживает перезапись frontmatter, но раздел уходит из документа: агент, создающий ADR, должен править второй файл, а индекс расходится с документами при переименованиях.
3. **Группировка по существующим полям** (`type` документа, `tags`). У решений нет ни типа, ни тегов; типы документов (`guide`, `specification`, `other`) темы не отражают.
4. **Поле `section` во frontmatter, а где его нет — вложенная папка.** Выбран.

Для ссылок рассматривались Markdown-ссылки на файлы (`[текст](decision-46 - Заголовок.md)`): они ломаются при переименовании документа, а имя файла решения содержит весь заголовок. Идентификатор `decision-N` не меняется никогда, и форма `[[decision-N]]` в проекте уже действует (правило 18).

## Decision

1. **Раздел документа** — путь через `/` (`"Агенты/HITL и инструменты"`). Источники по приоритету: поле `section` frontmatter; иначе путь вложенных папок относительно `backlog/docs` или `backlog/decisions`; иначе раздела нет, и документ лежит в корне своей группы.
2. **Решения размещаются только в корне `backlog/decisions/`**, раздел задаётся полем `section`. Документы могут задавать раздел и полем, и папкой (`backlog doc create -p`).
3. **Значение `section` — строка в кавычках** (правило 16). Сегменты обрезаются по пробелам, пустые отбрасываются, обратный слэш равен прямому. Нормализация — `normalizeSection` в `src/utils/docTree.ts`, общая для main-процесса и рендерера.
4. **Дерево в интерфейсе**: корневые группы «Решения (ADR)» и «Документы», внутри разделы и подразделы со счётчиком документов, затем документы без раздела. Документы сортируются по номеру из id, разделы по алфавиту. Раскрытые узлы запоминаются в `localStorage`; при поиске дерево раскрыто целиком; ветка выбранного документа раскрывается сама.
5. **Перекрёстная ссылка — идентификатор в двойных скобках**: `[[decision-N]]`, `[[doc-N]]`, `[[TASK-N]]`, `[[mem-N]]`, с необязательной подписью `[[decision-46|исполнитель инструментов]]`. Регистр идентификатора не важен.
6. **Открытие ссылки**: решение и документ — во вкладке «Документация» с кнопкой «Назад» (журнал до 50 переходов); задача — карточкой на доске; факт памяти — в разделе «Память». Ссылка на несуществующий объект показывается приглушённой с пунктирным подчёркиванием и не кликается.
7. **Упоминание идентификатора без скобок** (`decision-46`, `TASK-103`) становится ссылкой, только если такой объект есть в проекте. Внутри пути, имени файла (`doc-7 - Аудит.md`), более длинного слова и блока кода упоминание ссылкой не считается. Относительная Markdown-ссылка на файл `decision-N - ….md` или `doc-N - ….md` открывает тот же документ.
8. **Ссылки работают везде, где есть `MarkdownViewer`**: документы, описание задачи, память, чат AI Studio, Arena. Разбор — чистый модуль `src/utils/docRefs.ts`; данные и переходы даёт хук `useDocRefs`.
9. **`npm run lint:docs` проверяет**: `section` — непустая строка; если хотя бы один документ проекта имеет раздел, раздел обязателен у всех документов и решений; `[[decision-N]]` и `[[doc-N]]` вне блоков кода ведут на существующий документ.

## Consequences

- Плюс: структура видна в самом документе, перенос файлов не нужен, пути из старых задач остаются рабочими; Backlog.md CLI и веб-интерфейс продолжают читать документы и решения как раньше.
- Плюс: ссылка переживает переименование документа, а битая ссылка ловится линтером до коммита.
- Минус: `backlog doc update` и MCP `document_update` стирают `section` у документа. Линтер после этого падает с подсказкой вернуть поле; для новых документов надёжнее вложенная папка. Решений это не касается.
- Минус: веб-интерфейс Backlog.md дерево не показывает — разделы видит только ProjectHub.
- Минус: переход по ссылке на задачу или документ из карточки задачи закрывает карточку вместе с несохранёнными правками; предупреждение о несохранённых правках есть только у открытого документа.
- Долг: обратные ссылки («на этот документ ссылаются») и ссылки на заголовок внутри документа (`[[decision-46#Decision]]`) не делались. Закрыт вместе с подтверждением перехода из карточки задачи в [[decision-69]].
- Все существующие документы и решения ProjectHub разнесены по 16 разделам решений и 5 разделам документов.
- Реализация: TASK-121. Связанные решения: [[decision-3]] (Backlog.md как источник истины), [[decision-17]] (модальные окна через портал — окно создания документа переведено на `createPortal`), [[decision-67]] (разметка описания задачи).
