## Context

[[decision-68]] ввело перекрёстные ссылки по идентификатору и оставило три долга (его раздел Consequences):

- Переход по ссылке из описания задачи закрывает карточку: ссылка на документ или память переключает вкладку, и доска размонтируется; ссылка на другую задачу заменяет карточку. Правки формы (заголовок, статус, описание, метки, критерии) живут в состоянии `TaskDetailModal` и пропадали без вопроса. Подтверждение было только у изменённого документа.
- Из документа не видно, кто на него ссылается. В проекте 68 решений, и чтобы понять, какие задачи и решения опираются на ADR, приходилось искать идентификатор по тексту.
- Ссылка указывает только на документ целиком. ADR имеет устойчивые разделы (`Context`, `Decision`, `Consequences`), а ссылаются чаще всего на один из них.

Рассмотренные варианты.

**Где считать обратные ссылки.**

1. В рендерере по данным стора. Не подходит: в сторе лежит только описание задачи, а ссылка на решение обычно стоит в плане, заметках или итоге; текст остальных документов в стор не загружен.
2. Хранить список в самом документе (поле frontmatter или раздел в конце). Расходится с текстом при каждой правке, а `backlog doc update` стирает неизвестные поля ([[decision-68]]).
3. Через векторный индекс `.rag-index`. Индекс строится по смыслу, а не по ссылкам, и не покрывает задачи.
4. **Считать в main-процессе по файлам при загрузке списка документов.** Выбран: около двухсот небольших файлов читаются за миллисекунды, отдельное хранилище не нужно.

**Как записывать якорь.**

1. Slug в стиле GitHub (`#принятое-решение`). Автору приходится вычислять slug руками, для кириллицы правила неочевидны.
2. Точный текст заголовка. Ломается от регистра, двоеточия или разметки в заголовке.
3. **Текст заголовка, сравниваемый по ключу.** Выбран: ключ строится из букв и цифр, поэтому подходят и текст как в документе, и slug.

**Как защищать правки карточки.**

1. Не размонтировать доску при смене вкладки. Меняет устройство `ProjectWorkspace` и не спасает от ссылки на другую задачу.
2. Автосохранение карточки перед переходом. Запись в файл задачи без явного действия человека; недописанное описание попало бы в Backlog.md.
3. **Подтверждение перед переходом, как у документа.** Выбран.

## Decision

1. **Ссылка на заголовок** — `[[decision-46#Decision]]`, с подписью `[[decision-46#Decision|как выбирали]]`. Якорь — текст заголовка любого уровня. Относительная ссылка на файл с якорем (`decision-46 - ….md#Decision`) работает так же. Упоминание без скобок якоря не имеет.
2. **Сравнение по ключу** `headingAnchorKey` (`src/utils/docRefs.ts`): нижний регистр, всё кроме букв и цифр заменяется дефисом. `#Decision`, `#decision`, `#Принятое решение` и `#принятое-решение` находят соответствующий заголовок. При одинаковых заголовках берётся первый.
3. **Якорь действует для решений и документов.** У задачи и факта памяти якорь разбирается, но не используется: они открываются карточкой, а не текстом.
4. **Переход**: документ открывается, просмотр прокручивается к заголовку, заголовок кратко подсвечивается. Ссылка на заголовок открытого документа прокручивает без перехода и без записи в журнал «Назад». При смене документа просмотр начинается с начала.
5. **Заголовка нет** — документ открывается с начала, ссылка подчёркнута пунктиром и объясняет это в подсказке. `npm run lint:docs` падает на `[[decision-N#…]]` и `[[doc-N#…]]` с несуществующим заголовком в решениях и документах.
6. **Индекс связей** (`DocLinkIndex`) считает main-процесс: `buildProjectDocLinkIndex` в `docsService`, IPC `docs:linkIndex`. В нём обратные ссылки на решения и документы и ключи заголовков каждого документа. Стор обновляет индекс вместе со списком документов (`fetchDocs`): при выборе проекта, открытии вкладки, сохранении и создании документа.
7. **Источники обратных ссылок** — решения, документы и задачи из корня `backlog/tasks`. Задача читается из файла целиком. Ссылкой считается то же, что показывает ссылкой `MarkdownViewer`: `[[id]]`, упоминание идентификатора без скобок, относительная ссылка на файл. Не считаются: блоки кода, строчный код, frontmatter, ссылка документа на самого себя. Разбор — чистый модуль `src/utils/docBacklinks.ts`.
8. **Блок «На этот документ ссылаются»** выводится под текстом документа в режимах просмотра и раздельном; без входящих ссылок блока нет. Порядок: решения, документы, задачи, внутри вида по номеру. Элемент открывается тем же `useDocRefs`, что и ссылка в тексте.
9. **Подтверждение перехода** решает чистая функция `refLeaveGuards`. Карточка задачи с несохранёнными правками сообщает свой id в стор (`dirtyTaskId`); переход по ссылке к любому объекту, кроме этой же задачи, спрашивает подтверждение. Изменённый документ по-прежнему защищён при переходе к другому документу или памяти. Если теряются обе правки, вопросов два.
10. **Правкой карточки считается** отличие заголовка, статуса, майлстоуна, исполнителя, описания, меток и текстов критериев от записанного в файл (`isTaskDraftDirty`, `src/utils/taskDraft.ts`). Отметка критерия пишется в файл сразу и правкой не считается.

## Consequences

- Плюс: по ADR видно, какие решения и задачи на него опираются; ссылка ведёт к нужному разделу длинного документа.
- Плюс: правки карточки задачи не пропадают от клика по ссылке в её же описании.
- Плюс: битый якорь ловится линтером до коммита, как и битая ссылка.
- Минус: индекс не обновляется в момент изменения задачи агентом — только при следующей загрузке списка документов. Для блока справочного характера этого достаточно.
- Минус: переименование заголовка ломает ссылки на него. Линтер это покажет, но только для ссылок из решений и документов: задачи на якоря не проверяются.
- Минус: нормализация ключа заголовка продублирована в `scripts/validate-docs.mjs` — скрипт не импортирует TypeScript. Менять обе копии вместе.
- Долг: закрытие карточки задачи крестиком, `Escape` или кликом по фону подтверждения не спрашивает — это прежнее поведение, решение его не меняет.
- Долг: факты памяти и задачи из `backlog/completed` источниками обратных ссылок не являются; обратных ссылок на задачу нет.
- Реализация: [[TASK-122]]. Связанные решения: [[decision-68]] (формат ссылок, дерево разделов), [[decision-51]] (память проекта), [[decision-17]] (диалог подтверждения поверх модального окна).
