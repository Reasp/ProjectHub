## Context

Ревизия от 2026-09-10 показала, что Swarm Arena и Pick Winner в текущем виде теряют работу
агентов. Агенты (`claude -p`, `codex`, API-движок) пишут файлы в worktree, но не коммитят.
Дифф считается как `git diff base...branch` из основного репозитория и видит только коммиты,
поэтому он пустой. `merge --no-ff` вливает пустую ветку, после чего `removeWorktree --force`
уничтожает незакоммиченные изменения. Merge-конфликты не обрабатываются: основное дерево
остаётся в конфликтном состоянии, исходная ветка не восстанавливается. Ветки `swarm/*` и
`handoff/*` никогда не удаляются.

Рассматривались варианты: требовать от агентов коммитить самостоятельно (ненадёжно, зависит
от промпта и движка), хранить результаты как patch-файлы вне git (теряется история и
инструменты ревью), коммитить автоматически на стороне ProjectHub.

## Decision

1. **ProjectHub сам фиксирует результат агента в git.** По завершении агента (успех или
   ошибка) сервис делает в его worktree `git add -A` и коммит с сообщением
   `agent(<role>): <task или sessionId>` от имени технического автора
   `ProjectHub Agent <agent@projecthub.local>`. Если изменений нет, коммит не создаётся, а
   результат помечается «без изменений». Пользователь может отключить авто-коммит в настройках,
   тогда вместо коммита создаётся снапшот через `git stash create` и его hash сохраняется в
   сессии.
2. **Дифф считается по рабочему дереву worktree**, а не только по коммитам: `git diff <base>`
   внутри worktree плюс untracked-файлы. Так арена показывает результат даже до авто-коммита.
3. **Слияние безопасное и обратимое**: перед слиянием проверяется, что основное дерево чистое
   (иначе предлагается stash); используется `merge --no-ff --no-commit`; при конфликте
   выполняется `merge --abort`, восстанавливается исходная ветка и пользователю показывается
   список конфликтных файлов с возможностью разрешить их в UI или открыть в редакторе.
   Альтернатива слиянию: создание PR из ветки агента.
4. **Частичное принятие результата**: из ветки кандидата можно принять отдельные файлы или
   хуки (`git checkout <branch> -- <path>`), а не только всю ветку целиком.
5. **Удаление worktree никогда не теряет данные**: удаление возможно только если ветка имеет
   коммит с результатом или снапшот. Проигравшие кандидаты после Pick Winner удаляются вместе с
   веткой (`git branch -D`), но их последний коммит записывается в историю сессии для отката.
6. **Сборка мусора**: при старте приложения и по команде выполняется `worktree prune`,
   находятся worktree и ветки `swarm/*`, `handoff/*`, `task/*` без активной сессии и без
   задачи в работе, и пользователю предлагается удалить их.

## Consequences

- Плюс: Pick Winner, дифф, ревью и откат работают на стандартных объектах git.
- Плюс: история проекта содержит, кто из агентов что сделал, с ролью в сообщении коммита.
- Минус: в истории появляются технические коммиты. При слиянии рекомендуется squash или
  `--no-ff` с осмысленным сообщением, автор итогового коммита остаётся человеком.
- Минус: авто-коммит может зафиксировать мусор (логи, артефакты сборки). Сервис обязан
  уважать `.gitignore` и не коммитить `.worktrees/`, `node_modules/`, `dist/`.
