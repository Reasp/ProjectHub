## Context

Сейчас роль агента в Swarm и Handoff это строка `role` и текст `systemPromptAddon`, который
применяется только к API-движку и игнорируется для Claude CLI и Codex CLI. Пресеты ролей
(«Архитектор → Кодер → Тестировщик») захардкожены в UI модалки, main-процесс о них не знает.
Нет привязки роли к модели, инструментам, правам auto-approve и критериям готовности. Поле
`assignee` в задачах пишется, но не используется, поэтому назначить задачу конкретному агенту,
роли или машине нельзя.

Цель проекта: «разные агенты с разными ролями» на одном проекте и на нескольких компьютерах.
Для этого роль должна быть данными, которые можно хранить, версионировать, переиспользовать между
проектами и передавать по федерации.

## Decision

1. **Роль это файл-описание в формате markdown с frontmatter**, по аналогии с задачами:
   глобальные роли в `<userData>/roles/<slug>.md`, проектные в `<project>/.projecthub/roles/`
   (проектные переопределяют глобальные с тем же `slug`). Поля frontmatter:
   `slug`, `name`, `engine` (`claude-cli | codex-cli | gemini-cli | api`), `model`,
   `provider`, `tools` (allow-список инструментов), `permissions` (профиль auto-approve:
   чтение, запись, команды, подагенты, deny-список команд), `dod` (чеклист Definition of Done),
   `handoffTo` (роли, которым можно передать результат), `maxTurns`, `budgetUsd`.
   Тело файла это системный промпт роли.
2. **Роль применяется одинаково во всех движках** через единый адаптер: для Claude CLI через
   `--append-system-prompt`, `--allowedTools`/`--disallowedTools`, `--model`, `--max-turns`;
   для Codex и Gemini CLI через их аналогичные флаги; для API-движка через system prompt и
   фильтр инструментов. Движок, не умеющий выразить ограничение, обязан сообщить об этом, а не
   молча проигнорировать.
3. **Стартовый набор ролей поставляется с приложением**: `architect` (спецификация и план,
   только чтение), `implementer` (запись в worktree, команды сборки), `reviewer` (чтение и
   комментарии, без записи), `tester` (запуск тестов, правка только `tests/`), `doc-writer`
   (запись только в `backlog/docs`). Пользователь редактирует их в UI и создаёт свои.
4. **Назначение задачи**: поле `assignee` задачи Backlog.md принимает значения вида
   `agent:<roleSlug>` и `agent:<roleSlug>@<hostId>`. ProjectHub показывает назначение на карточке,
   а планировщик (локальный или федеративный) запускает агента с этой ролью в worktree задачи.
   Человеческие значения `assignee` остаются как есть.
5. **Handoff строится из ролей**, а не из свободных этапов: конвейер это список `roleSlug` с
   правилом передачи (`handoffTo`). Результат этапа передаётся не сырым stdout, а структурированным
   артефактом: коммит в общем worktree, файл отчёта `.projecthub/handoff/<stage>.md` и краткое
   резюме ограниченной длины.

## Consequences

- Плюс: роли переносимы между проектами и компьютерами (обычные файлы в git или userData).
- Плюс: права и стоимость ограничиваются на уровне роли, а не на уровне отдельного запуска.
- Минус: появляется ещё один формат файлов и его валидация; линтер документации расширяется на
  `roles/`.
- Минус: не все движки поддерживают все ограничения. Матрица поддержки должна быть видна в UI.
- Реализация: TASK-60, использование в контексте агента TASK-64, в федерации TASK-66.

### Уточнения по факту реализации (TASK-60, 2026-09-11)

- У установленной версии Claude CLI (`claude --help`) **нет** флага `--max-turns` — `maxTurns`
  роли для `claude-cli` обеспечивается на уровне ProjectHub (счётчик `assistant`-событий
  stream-json с принудительным завершением процесса), а не нативным флагом CLI. `--allowedTools`/
  `--disallowedTools`, `--append-system-prompt`, `--model` и `--max-budget-usd` (для `budgetUsd`)
  подтверждены и применены как есть.
- `codex`/`gemini` CLI не установлены на машине реализации: флаги адаптера
  (`codex exec --json --sandbox --ask-for-approval`, `gemini --approval-mode --output-format json`)
  взяты из актуальной публичной документации, а не проверены эмпирически — нужен ручной
  smoke-test на машине с этими CLI перед тем, как считать AC #2/#3 полностью закрытыми.
- `assignee` в GUI реализован как текстовое поле с автодополнением (`agent:<slug>`), а не строгий
  `<select>` — человек может ввести и произвольное имя, и `agent:<slug>@<hostId>`; `hostId` вне
  локального хоста сейчас явно отклоняется («федерация ещё не реализована», задел под TASK-66).
- Handoff по цепочке `handoffTo` проверяется мягко (предупреждение в UI, не блокировка запуска).
- Поле `cliCommand` в `AgentSlotConfig` удалено как мёртвый код (было не задействовано нигде);
  для кастомных CLI-движков сверх `claude-cli`/`codex-cli`/`gemini-cli` инфраструктуры не вводилось.
