# Векторный RAG для документации проекта

Этот документ описывает, как в проекте организован смысловой поиск по документации — и для человека, и для агента. Это отдельная система от **GitNexus**: GitNexus строит граф кода (вызовы, зависимости, impact-анализ), а этот RAG — семантический индекс по markdown-документам в `backlog/docs/` и `backlog/decisions/`.

---

## 1. Архитектура и компоненты

- **Эмбеддинги**: Локальная модель `Xenova/all-MiniLM-L6-v2` через `@huggingface/transformers`, работающая полностью автономно без внешнего API.
- **Векторная база**: [LanceDB](https://lancedb.github.io/lancedb/), хранится в каталоге `.rag-index/` и коммитится в Git.
- **Кэш модели**: `.rag-cache/` (добавлен в `.gitignore`, ~90MB весов модели).

---

## 2. Основные команды

```bash
npm run index-docs   # (пере)собрать векторный индекс из backlog/docs/**, backlog/decisions/**
npm run rag-search -- "запрос"   # быстрый семантический поиск из терминала
npm run rag-server   # запуск MCP-сервера docs-rag для AI-агентов (stdio)
```

---

## 3. MCP-инструменты для AI-агентов

Сервер `scripts/rag/rag-server.mjs` регистрируется в `.mcp.json` под именем `docs-rag` и предоставляет следующие инструменты:

- `search_docs(query, topK?)`: Смысловой поиск с возвратом наиболее релевантных фрагментов документации.
- `list_docs()`: Список всех проиндексированных файлов базы знаний.
- `get_doc(file)`: Чтение полного содержимого документа.
