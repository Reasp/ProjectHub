# Векторный RAG для документации

Этот документ описывает, как в проекте организован смысловой поиск по документации —
и для человека, и для агента. Это отдельная система от **GitNexus**: GitNexus строит
граф кода (вызовы, зависимости, impact-анализ), а этот RAG — индекс по markdown-докам
в `backlog/docs/` и `backlog/decisions/` (отдельной верхнеуровневой `docs/` в проекте нет —
вся документация живёт внутри `backlog/`).

## Почему не через GitNexus

GitNexus индексирует репозиторий как код. Документации нужен другой тип поиска —
смысловое сходство текста, а не граф вызовов. Смешивание двух типов данных в одном
индексе не даёт выигрыша ни там, ни там, поэтому это два независимых инструмента.

## Как это устроено

- **Эмбеддинги** — локальная модель `Xenova/all-MiniLM-L6-v2` через `@huggingface/transformers`,
  без внешнего API и без сети (после первого скачивания модели).
- **Индекс** — [LanceDB](https://lancedb.github.io/lancedb/), хранится как обычные файлы
  в `.rag-index/`. Эти файлы **коммитятся в git** — индекс не нужно пересобирать после
  клонирования репозитория, если документация не менялась.
- **Кэш модели** — `.rag-cache/`, в `.gitignore` (это веса модели, ~90MB, не текст проекта).

## Команды

```bash
npm run index-docs   # (пере)собрать индекс из backlog/docs/**, backlog/decisions/**
npm run rag-search -- "как устроен world graph"   # быстрый поиск из терминала
npm run rag-server   # запустить MCP-сервер для агента (stdio)
```

Индекс нужно пересобирать вручную после заметных изменений в документации —
автоматической синхронизации по git-хуку пока нет (открытый вопрос, см. README.md).

## MCP-инструменты для агента

Сервер `scripts/rag/rag-server.mjs` регистрируется в `.mcp.json` под именем `docs-rag`
и даёт три инструмента:

- `search_docs(query, topK?)` — смысловой поиск, возвращает наиболее релевантные
  фрагменты документации с указанием файла и раздела.
- `list_docs()` — список всех проиндексированных файлов.
- `get_doc(file)` — полное содержимое одного файла, когда фрагмента из поиска мало.

Агент должен вызывать `search_docs` перед тем, как отвечать на вопросы про архитектуру,
конвенции или устройство подсистем проекта, а не полагаться только на память.
