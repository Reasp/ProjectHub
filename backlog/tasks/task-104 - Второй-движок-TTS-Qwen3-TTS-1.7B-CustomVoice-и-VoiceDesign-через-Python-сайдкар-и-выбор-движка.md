## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Сейчас локальный TTS — это голоса Piper через sherpa-onnx в отдельном `utilityProcess` ([[decision-25]], [[decision-34]], TASK-69). Качество «medium»-голосов заметно синтетичнее современных моделей, управления эмоцией и темпом нет, а «свой голос» ограничен импортом готовой `.onnx`-модели.

Добавить второй движок — Qwen3-TTS 1.7B (12 Гц), две модели:

- **`Qwen/Qwen3-TTS-12Hz-1.7B-CustomVoice`** — 9 пресет-голосов (Vivian, Serena, Ryan …) плюс управление подачей через инструкцию на естественном языке (`generate_custom_voice(text, speaker, instruct)`).
- **`Qwen/Qwen3-TTS-12Hz-1.7B-VoiceDesign`** — голос по текстовому описанию (`generate_voice_design`): тембр, возраст, манера.

Факты по моделям (карточки Hugging Face, проверено 2026-09-21): лицензия Apache-2.0; 1.7B, safetensors BF16 (≈3.5 ГБ на модель); запуск — Python-пакет `qwen-tts` (PyTorch, CUDA или CPU, опционально FlashAttention 2); 10 языков, включая русский; ONNX/GGUF-сборок нет.

## Чем это ломает текущую архитектуру

1. **Нет Node-рантайма.** Piper крутится через sherpa-onnx в `utilityProcess` без Python. Qwen3-TTS — это PyTorch, то есть отдельный Python-сайдкар с собственным venv, по образцу LightRAG (`scripts/lightrag`, `features.lightrag`). Значит фича опциональная и по умолчанию выключенная (правило 7 infra-dev): ~7 ГБ весов на две модели плюс torch.
2. **Нет понятия «движок» у голоса.** `TtsVoiceDefinition` (`ttsVoiceRegistry.ts`) описывает именно Piper: `modelFile`, `tokens`, `config`, архив sherpa-onnx. Нужен `engine: 'piper' | 'qwen'` и маршрутизация в сервисе озвучки, а Piper остаётся движком по умолчанию и продолжает работать без Python.
3. **Сохранение «сконструированного» голоса.** У VoiceDesign голос — это не файл модели, а описание: в реестре появляется запись без весов (модель одна на все такие голоса), с пробой перед сохранением (как `ttsVoiceProbe` для импортированных).

Переиспользуется как есть: разбиение текста на фрагменты (`ttsTextSplit`), коды ошибок и их локализация (`ttsErrorCodes`), выбор устройства вывода, `ttsMuted`, прогресс загрузки моделей (`ttsDownloadProgress`).

## Открытые вопросы для спайка

- Задержка первой и последующих фраз на CPU против CUDA на машине пользователя; нужен ли режим «греть модель заранее» и выгрузка по простою (VRAM/RAM).
- Стриминг: отдаёт ли `qwen-tts` аудио по частям или только целым WAV — от этого зависит, останется ли пофразовая озвучка отзывчивой.
- Частота дискретизации выхода (в карточке не указана; «12 Hz» — частота токенов кодека, не аудио) и приведение к текущему конвейеру воспроизведения.
- Русский язык: качество и ударения в сравнении с `ru_RU-irina`, чтобы решить, делать ли Qwen движком по умолчанию при включённой фиче.

## Спайк 2026-09-21: фича отложена, решение — [[decision-50]]

Проверены все четыре открытых вопроса задачи. Итог: движок в текущей реализации не проходит по
скорости, работа приостановлена до выполнения условий decision-50 п. 3 (появление потоковой
генерации, сборки без Python с RTF < 1 или заметно более быстрого железа). Задача остаётся в
`To Do` как ожидающая внешнего условия; код не писался.

**Условия замеров.** Windows 10, RTX 2080 8 ГБ (≈2.8 ГБ заняты другими процессами), Python
3.11.15, `torch` 2.11.0+cu128, `qwen-tts` 0.1.1, `transformers` 4.57.3, bf16, без FlashAttention
(на Turing не поддерживается). Референс Piper `ru_RU-irina-medium` снят на той же машине тем же
текстом через `sherpa-onnx-node` из `node_modules`.

| Метрика | Qwen 1.7B CustomVoice | 1.7B VoiceDesign | 0.6B CustomVoice | Piper irina |
|---|---|---|---|---|
| RTF (GPU, прогрето) | 2.75–2.82 | 2.80–2.81 | 2.72–2.78 | 0.13–0.16 |
| Фраза 5–8 с звука | 14–23 с | 13–20 с | 11–15 с | 0.5–0.7 с |
| Загрузка модели | 3.2 с | 3.2 с | 2.3 с | 1.9 с |
| VRAM после загрузки / пик | 4.2 / 4.6 ГБ | 4.2 / 4.6 ГБ | 2.2 / 2.5 ГБ | — |
| Частота выхода | 24 кГц | 24 кГц | 24 кГц | 22.05 кГц |

Пауза до первого звука на коротких фрагментах (так режет текст `ttsTextSplit`), 1.7B
CustomVoice: «Готово.» — 2.94 с на 1.04 с звука; «Сборка прошла.» — 3.82 с на 1.36 с;
«Линтер чист, тесты зелёные.» — 7.69 с на 2.80 с; фраза на 58 символов — 11.09 с на 4.00 с.
У Piper первый чанк — 132–263 мс (TASK-69).

**Ответы на открытые вопросы задачи.**

1. *Задержка CPU против CUDA.* CUDA: RTF ≈ 2.8, пауза 3–11 с. CPU (fp32, 8 потоков): RTF 7.61
   (53 с на 7 с звука), RSS 9.6 ГБ — неприменимо. «Греть модель заранее» не спасает: загрузка
   весов всего 2–3 с, всё время уходит на саму генерацию.
2. *Стриминг.* Настоящей потоковой генерации в пакете нет: `generate_custom_voice` /
   `generate_voice_design` возвращают готовый `Tuple[List[np.ndarray], int]`, а
   `non_streaming_mode=False`, по документации самого метода, лишь имитирует потоковый **ввод
   текста**. Карточка модели при этом обещает «Streaming ✅» — это про модель, не про пакет.
   Батч из трёх фраз даёт RTF 1.1–1.6, но отдаёт результат целиком, то есть ухудшает паузу.
3. *Частота дискретизации.* 24 кГц (`sample_rate=24000` в конфигурации кодека, подтверждено
   выходом). Приводить ничего не нужно: `ttsPlayer` создаёт `AudioContext` по частоте модели,
   как и для 22.05 кГц Piper.
4. *Русский против `ru_RU-irina`.* Прогон синтеза через тот же `Xenova/whisper-base`, что стоит
   в приложении: средний WER 32% (CustomVoice), 27% (VoiceDesign), 37% (Piper). По
   разборчивости проигрыша нет — проигрыш только в скорости. Выборка мала (3 фразы), образцы
   сохранены для прослушивания человеком. Важно: среди 9 пресет-голосов нет ни одного с родным
   русским (китайские ×5, английские ×2, японский, корейский).

**Дополнительно найдено.**

- 0.6B при втрое меньших весах даёт тот же RTF — узкое место не в размере talker-модели, а в
  цене шага авторегрессивной генерации; более быстрый GPU выигрыш даст, но не пропорциональный.
- fp16 не быстрее bf16 (2.93–3.01 против 2.75–2.82) — дело не в эмуляции bf16 на Turing.
- VoiceDesign воспроизводим: при одинаковом seed два прогона одного `instruct` дают побитово
  одинаковый звук (максимальная разница отсчётов 0.0). То есть «сконструированный» голос
  хранится как (описание, seed) — запись без файла модели, как и предполагалось. Детерминизм
  проверен на одной машине и версии torch.
- `huggingface.co` в этой сети отвечает TLS-сбросом (DNS тоже отваливается), `huggingface_hub`
  на этом падает целиком; 9 ГБ весов скачались только через `hf-mirror.com` пофайловым `curl` с
  докачкой. Для будущей реализации адрес хаба обязан быть параметром.

**Что пригодится при возобновлении.** Реестр голосов (`ttsVoiceRegistry`) описывает именно Piper
(`modelFile`, `tokens`, архив sherpa) — поле `engine` и маршрутизация в `piperTtsService`
остаются в силе как требование; переиспользуются `ttsTextSplit`, `ttsErrorCodes`,
`ttsDownloadProgress`, выбор устройства вывода и `ttsMuted`. В рендерере тип
`TtsEngine = 'system' | 'piper'` (`voiceService`) — точка расширения. Требования к любому
будущему движку сведены в decision-50 п. 4.
