## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Сейчас языка голосового ввода в настройках нет: он всегда равен языку интерфейса. `VoiceControlWidget` при каждой смене языка (кнопки EN / RU в шапке, `Header.tsx`) вызывает `voiceService.setLanguage`, и тот сохраняет значение в `config.language`.

Из этого `config.language` берут язык:
- Whisper (`dispatchToWhisper` → `transcribeLocalWhisper(pcm, language)`, облачные провайдеры);
- Web Speech API (`recognition.lang` = `ru-RU` / `en-US`);
- классификатор команд и озвучка ответов (`speakLang`).

Как это мешает:
- При интерфейсе на EN русская речь не распознаётся как русская: Whisper переводит её на английский. Говорить по-русски при английском интерфейсе нельзя.
- Нельзя диктовать по-английски, не переключая весь интерфейс.
- Нет автоопределения языка, хотя Whisper его умеет.

Нужно: в настройках голоса (`VoiceSettingsModal`) выбор «Язык распознавания» с вариантами «Как интерфейс» (по умолчанию, нынешнее поведение), «Русский», «English», «Автоопределение» (если провайдер Whisper его поддерживает; для Web Speech API автоопределения нет — показать подсказку и откатиться на язык интерфейса).

Выбранный язык распознавания нельзя смешивать с языком интерфейса: смена EN / RU в шапке не должна перезаписывать явный выбор. Нужно решить, по какому языку работают:
- разбор команд регулярками (фразы команд из `voiceCommandPhrases`);
- классификатор (`voice:classifyCommand`, поле `language`);
- язык озвучки ответа.

Разумный вариант — язык распознанной фразы, если Whisper его вернул, иначе язык распознавания, иначе язык интерфейса. Выбор зафиксировать в ADR.

Миграция: у существующих пользователей `config.language` уже хранит язык интерфейса. Новое поле (например, `recognitionLanguage: 'ui' | 'ru' | 'en' | 'auto'`) по умолчанию `ui`, чтобы поведение не поменялось само.
<!-- SECTION:DESCRIPTION:END -->
