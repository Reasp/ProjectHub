## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
### Почему

После TASK-121 ([[decision-68]]) перекрёстные ссылки `[[decision-N]]`, `[[doc-N]]`, `[[TASK-N]]`, `[[mem-N]]` открываются по клику, но остались долги, записанные в Consequences decision-68 и в заметках TASK-121:

- Переход по ссылке из описания задачи переключает вкладку, доска размонтируется, и несохранённые правки карточки задачи пропадают без вопроса. У открытого документа такое подтверждение есть.
- Из документа не видно, кто на него ссылается: чтобы понять, какие решения и задачи опираются на ADR, приходится искать по тексту.
- Сослаться можно только на документ целиком, а не на его раздел (`## Decision`, `## Consequences`).
- В живом окне не проверялись переход по `[[mem-N]]` в раздел «Память» и вид ссылки на несуществующий объект.

### Цель

- Правки карточки задачи не теряются молча при переходе по ссылке.
- В просмотре документа виден блок «На этот документ ссылаются».
- `[[decision-46#Decision]]` открывает документ и прокручивает к разделу.
- Непроверенное в TASK-121 проверено в живом окне.

### Ограничения

- Решения остаются в корне `backlog/decisions/`: вложенные папки ломают нумерацию Backlog.md.
- `backlog doc update` и MCP `document_update` стирают `section` у документа — после обновления поле вернуть.
- Если `ProjectHub.exe` запущен, `pack:win` не обновит exe: проверять свежий `dist-electron` через `node_modules/electron/dist/electron.exe` с отдельным `--user-data-dir`, приложение владельца не закрывать.

## Implementation Notes

### Что сделано

- **Подтверждение в карточке задачи**: `TaskDetailModal` сравнивает форму с записанным в файл (`isTaskDraftDirty`) и сообщает стору `dirtyTaskId`; `useDocRefs.open` перед переходом спрашивает подтверждение. Какие вопросы нужны, решает чистая функция `refLeaveGuards`. Ссылка на ту же задачу вопроса не вызывает.
- **Обратные ссылки**: индекс считает main-процесс (`buildProjectDocLinkIndex`, IPC `docs:linkIndex`) по файлам решений, документов и задач; стор обновляет его в `fetchDocs`. Блок `DocBacklinks` под текстом документа.
- **Ссылка на заголовок**: `[[id#Заголовок]]`, `[[id#Заголовок|подпись]]`, якорь относительной ссылки на файл. Сравнение по ключу `headingAnchorKey`. Заголовки `MarkdownViewer` получили `data-heading-key`, `DocsRagView` прокручивает к разделу и подсвечивает его; при смене документа просмотр начинается с начала.
- **Линтер**: `[[decision-N#…]]`/`[[doc-N#…]]` с несуществующим заголовком — ошибка.
- **Решение**: decision-69; в decision-68 долг помечен закрытым. Правило 13 `infra-dev.md` дополнено, `sync-rules` и `index-docs` выполнены.
