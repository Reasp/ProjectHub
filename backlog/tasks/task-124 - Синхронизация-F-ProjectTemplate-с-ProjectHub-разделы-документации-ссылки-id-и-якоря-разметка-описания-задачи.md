## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
### Почему

В ProjectHub появились правила оформления документации и задач ([[decision-67]], [[decision-68]], [[decision-69]]), а шаблон `F:\ProjectTemplate` (источник файлов скилла `init-dev-project`) их не знает: новые проекты создаются со старым форматом.

### Цель

Перенести в шаблон правила и проверки:

- раздел дерева документации — поле `section` или вложенная папка;
- перекрёстные ссылки `[[id]]` и ссылки на заголовок `[[id#Заголовок]]`;
- описание задачи Markdown-разметкой, а не сплошной строкой.

### Ограничения

- Направление хаб → шаблон, выборочно: собственные доработки шаблона (нумерация правил, git-хуки, статусы Human) не затирать.
- Коммит в репозитории шаблона — только по явной просьбе пользователя.

## Implementation Notes

Правки — только в рабочем дереве `F:\ProjectTemplate`, без коммита.

### Что перенесено

- `scripts/doc-rules.mjs` (новый) — чистые функции: `headingAnchorKey`, `sectionFieldError`, `isInSubfolder`, `extractDocRefs`, `buildDocEntry`, `crossCheckDocs`. В хабе эта логика лежит прямо в `validate-docs.mjs`; в шаблоне вынесена ради тестов `node --test`.

- `scripts/validate-docs.mjs` — вызывает модуль: формат `section`, обязательность раздела, ссылки `[[decision-N]]`/`[[doc-N]]`, якоря.

Разослано `npm run sync-rules`.
