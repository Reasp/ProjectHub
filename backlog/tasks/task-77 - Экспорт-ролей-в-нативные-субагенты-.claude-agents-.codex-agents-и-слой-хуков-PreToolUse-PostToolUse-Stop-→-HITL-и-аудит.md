## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Роли ProjectHub (decision-9, TASK-60) применяются только когда агента запускает ProjectHub. Когда разработчик открывает `claude` или `codex` во встроенном терминале, роли и HITL-политики не действуют. Оба движка поддерживают нативные субагенты и хуки: Claude Code — `.claude/agents/*.md` (frontmatter: name, description, tools, model) и хуки `PreToolUse/PostToolUse/Stop/SessionStart/…` в `settings.json`; Codex — `.codex/agents/*.toml` (name, model, effort, sandbox, mcp, skills) и хуки `SessionStart/PreToolUse/PermissionRequest/PostToolUse/UserPromptSubmit/Stop` в `config.toml`/`.codex/hooks.json`; скиллы — `.agents/skills/*/SKILL.md` (общий каталог с Antigravity). Задача делает ProjectHub единым источником ролей и политик для всех поверхностей (doc-10).

## Что сделать
1. `roleExport.ts` (чистый модуль, тесты): роль → `.claude/agents/<slug>.md` (tools по `CLAUDE_TOOLS_BY_CATEGORY`, model по тиру/ид), → `.codex/agents/<slug>.toml` (sandbox из permissions, effort), → описание в `.agents/` для Antigravity. Идемпотентная синхронизация с маркером «generated by ProjectHub» и без перезаписи ручных файлов.
2. Хуки: генерация проектных хуков, вызывающих локальный CLI/HTTP встроенного MCP-сервера ProjectHub: `PreToolUse` → проверка политики роли/HITL (`exit 2` = отказ; запрос в очередь HITL с ожиданием решения), `PostToolUse` → запись в аудит-лог (decision-10) с `duration_ms`, `Stop` → запуск чеков и уведомление; для Claude — `settings.json` проекта, для Codex — `hooks.json`. Хуки не должны ломать работу, если ProjectHub не запущен (таймаут + fail-open с логом, настраиваемо).
3. UI в менеджере ролей: «Синхронизировать в проект» с предпросмотром файлов; индикатор расхождений (роль изменена — файлы устарели).
4. Менеджер скиллов: список `.claude/skills`, `.agents/skills` проекта, копирование между проектами шаблона.
<!-- SECTION:DESCRIPTION:END -->
