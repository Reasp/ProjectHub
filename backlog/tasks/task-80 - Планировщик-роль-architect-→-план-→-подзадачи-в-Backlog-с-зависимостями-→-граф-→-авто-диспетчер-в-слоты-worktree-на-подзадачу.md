## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Devin/Jules продают «fire-and-forget» выполнение больших задач; Claude Code — plan mode и параллельные субагенты; Codex Ultra — «maximum reasoning with automatic task delegation». В ProjectHub есть режимы `fan_out` (все делают одно) и `handoff` (конвейер), но нет декомпозиции: большую задачу нельзя разбить на подзадачи с зависимостями и раздать нескольким агентам параллельно. Backlog.md уже поддерживает `parentTaskId` и `dependencies` — их и используем как модель плана (doc-10).

## Контур
1. Роль `architect` получает задачу + контекст и возвращает структурированный план: список подзадач (title, description, AC, dependencies, оценка размера, рекомендованный тир модели), зафиксированный как `implementationPlan` родительской задачи и как реальные подзадачи в `backlog/tasks/` (через `backlogTaskCreate`, `parentTaskId`, `dependencies`).
2. Человек правит план в UI (граф зависимостей, перетаскивание, слияние/разделение узлов) и подтверждает — без подтверждения ничего не запускается.
3. Диспетчер: подзадачи без незакрытых зависимостей запускаются параллельно в режиме «до готовности» (каждая — свой worktree/ветка от базовой), с лимитом параллельности и общим бюджетом; при завершении подзадачи её ветка сливается в интеграционную ветку родителя (decision-8), после чего запускаются зависимые.
4. Конфликты слияния — HITL-запрос с диффом; провал подзадачи — остановка зависимых и уведомление.
5. По завершении всех — родительская задача → Review с сводкой (подзадачи, стоимость, чеки).

## Что сделать
- `planSchema.ts` (zod, валидация плана, тесты на циклы зависимостей/топологическую сортировку) + `planDispatcher.ts` (чистая логика готовности узлов, тесты) + `planService.ts`.
- Промпт роли architect для структурированного плана в `contextBuilder`.
- UI: вкладка «План» в карточке задачи — граф (DAG) с состояниями узлов, кнопки «Сгенерировать план», «Утвердить и запустить», «Остановить всё».
