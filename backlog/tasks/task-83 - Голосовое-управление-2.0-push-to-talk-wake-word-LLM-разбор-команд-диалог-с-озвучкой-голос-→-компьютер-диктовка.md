## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Голосовой модуль ProjectHub уже силён: hands-free VAD, локальный Whisper в воркере, 48 интентов в `voiceCommandParser` (навигация, git, процессы, AI-сессии, чтение задач), настраиваемые фразы, выбор устройств, TTS через системный синтез (Piper — TASK-69). Пробелы: команды понимаются только по regex-фразам (нет свободной речи), нет глобального push-to-talk вне окна, нет wake word, ответы агента не озвучиваются (нет диалога), нет голосового управления компьютером и диктовки в чужие окна. Задача закрывает это без привязки к вендору моделей (decision-26 п. 0).

## Что сделать
1. **Push-to-talk и wake word.** Глобальная горячая клавиша через Electron `globalShortcut` (по умолчанию `Ctrl+Shift+Space`, удержание = запись, отпускание = отправка), работает при свёрнутом окне; индикатор в трее (`trayService`, TASK-63). Wake word без внешних библиотек: в hands-free режиме первая фраза чанка сверяется с настраиваемым ключевым словом («Хаб», «Привет, Хаб») по транскрипту Whisper; опционально — Porcupine/openWakeWord как плагин, если понадобится точность (не по умолчанию: openWakeWord — Python).
2. **LLM-разбор свободных команд.** Если `voiceCommandParser` не распознал фразу — она уходит классификатору на **любой настроенной модели** (по умолчанию локальная через Ollama/профиль TASK-70, cheap-тир TASK-79): структурированный ответ `{intent, payload, confidence}` по списку известных интентов + `unknown`; при низкой уверенности — переспросить голосом. Промпт и схема — чистый модуль с тестами; кэш частых фраз.
3. **Диалог с агентом.** Интент `send_prompt` получает продолжение: финальный ответ агента (AI Studio/Swarm) кратко озвучивается через TTS (Piper, длина ответа ограничена, код и диффы не читаются — только сводка), HITL-вопросы агента озвучиваются и принимают голосовой ответ (`agent_approve`/`agent_reject`/`agent_select_option` уже есть). Barge-in: речь пользователя останавливает озвучку (VAD → `stop_reading`).
4. **Голосовое управление компьютером.** Интенты вида «кликни …», «напечатай …», «открой окно …», «прокрути вниз» не парсятся регулярками, а передаются агенту с инструментами `computer_*` (TASK-82) как задача в одном ходе с HITL-политикой computer-use; результат озвучивается («Готово», «Не нашёл кнопку Сохранить»).
5. **Системная диктовка.** Режим «диктовать в активное окно»: распознанный текст печатается через `computer_type` в любое приложение (с подтверждением при первом включении и allowlist окон TASK-82); интеллектуальная пунктуация — через модель (п. 2) при включённой настройке.
6. **Гигиена**: интенты и фразы для новых режимов в `voiceCommandPhrases` (ru/en), i18n, настройки в `VoiceSettingsModal` (вкладка «Диалог и диктовка»), unit-тесты для классификатора/маршрутизации.

## Вне scope
Piper TTS (TASK-69), сам прокси computer-use (TASK-82), обучение wake word.

## Implementation Notes

## Что сделано по пунктам плана

**1. Push-to-talk и wake word.**
`electron/services/pushToTalkPolicy.ts` — чистый модуль: валидация accelerator (отвергает чистые модификаторы и F12), санитайзер настроек, конечный автомат удержания. Electron `globalShortcut` не даёт keyup (electron#26301 закрыт), нативных перехватчиков клавиатуры в проекте нет, а `npmRebuild: false` делает новую нативную зависимость дорогой. Удержание восстанавливается по автоповтору `RegisterHotKey`: Chromium не передаёт `MOD_NOREPEAT`, поэтому зажатая клавиша шлёт повторные срабатывания. Дедлайн адаптивный — первый по худшему случаю (1200 мс), дальше наблюдаемый интервал × 2.5. Вне Windows режим `hold` понижается до `toggle` (автоповтора у горячих клавиш там нет).
`electron/services/voiceHotkeyService.ts` — регистрация, таймер, персист `<userData>/voice-hotkey.json`. Побочные эффекты навешивает `main.ts` через handlers, как у `computerUseService`.
Трей: в `TrayState` добавлено `recording`, в `TrayService` — отдельный флаг `setRecording` и `applyIcon()`. Флаг отдельный намеренно: `notificationService.refreshTray()` дёргает `setState` на каждом событии шины и затёр бы индикацию. Приоритет `attention` > `recording` > `working` > `idle`. Четвёртая иконка сгенерирована `scripts/gen-tray-icons.mjs`.
`main.ts`: инициализация в `whenReady`, `shutdown()` в `performGracefulShutdown`, плюс страховочный `app.on('will-quit')` → `globalShortcut.unregisterAll()` (его в проекте не было вовсе).
Рендерер: `voiceService.beginPushToTalk/endPushToTalk`, отдельная ветка в `processAudioChunkVAD` — при удержании пишется всё подряд, детектор тишины фразу не режет; ограничение 60 с от «залипшей» клавиши.
Wake word: `src/services/wakeWord.ts` — сверка по словам (а не по подстроке: «хабар» не обращение), регистр и «ё», окно 8 с на команду отдельной фразой.

**2. LLM-классификатор.**
`electron/services/voiceCommandClassifier.ts` — каталог интентов как данные, промпт, толерантный парсер, LRU-кэш (64 записи, TTL 24 ч). JSON-режима нет ни у одного провайдера проекта, у Anthropic его нет вовсе, tool-use не умеет часть локальных моделей — поэтому контракт: один JSON-объект, извлекаемый `extractJsonObject`, плюс запасной формат «голый идентификатор интента». Номера модель даёт с единицы, наружу уходит индекс с нуля. Порог уверенности 0.6 не покидает main: в рендерер уходит флаг `confident`.
`aiAgentService.complete()` — одноразовый вызов без инструментов, без `buildSystemPrompt` (там вшита преамбула «You are Claude Code»), `temperature: 0`, свой таймаут. Через `claudeBridgeService` идти было нельзя: при `provider: anthropic` без ключа он запускает процесс Claude CLI. Вендорского дефолта модели нет — при пустой модели честная ошибка (decision-26 п. 0).
`electron/services/llmEndpoint.ts` — разрешение адреса OpenAI-совместимых провайдеров вынесено из приватного метода и покрыто тестами.
Порядок разбора: ключевое слово → регулярки → модель. Привычные команды остаются мгновенными и бесплатными.

**3. Диалог с озвучкой.**
`src/services/ttsSummary.ts` — снятие кода, диффов, таблиц и разметки, обрезка по границе предложения. `useAIStudioStore` в `onAIComplete` шлёт событие `projecthub:agent-answer`; решение, читать ли вслух, принимает голосовой модуль.
Вопросы агента озвучиваются подпиской на `useHitlStore`. Голосовой ответ на HITL теперь покрывает **общую** очередь, а не только `pendingApprovals` AI Studio: запросы внешних сессий и `computer_action` от MCP-моста туда не попадают и голосом раньше были недоступны.
Barge-in: `src/services/bargeInDetector.ts` работает **внутри** существующего гейта `ttsMuted`, второго механизма глушения не заводилось. Нужны и громкость (порог 0.08 против 0.012 у обычного VAD), и длительность 350 мс — случайный щелчок чтение не прервёт.

**4. Голос → компьютер.**
IPC `voice:runComputerTask` — один ход агента, где `allowedToolNames` ограничен именами `computer_*`, поэтому родные инструменты (чтение файлов, запуск команд) в голосовую команду не попадают. HITL, allowlist, аудит и kill-switch остаются внутри `computerUseService.callTool` — не дублируются и не обходятся. Есть собственный таймаут: `streamChat` при отмене не зовёт ни `onComplete`, ни `onError`, и промис завис бы.

**5. Системная диктовка.**
IPC `voice:dictateText` → `computer_type`; опциональная пунктуация через `complete()`, при недоступности модели печатается исходный текст. В рендерере режим включается с подтверждением при первом включении (`dictationConfirmed`), выход — фразой «конец диктовки». Ключевое слово в режиме диктовки намеренно не применяется: диктуют прозу.

**6. Гигиена.**
`dictation_start`/`dictation_stop` в `voiceCommandPhrases` (новая категория `dialog`, фразы ru/en), i18n ru/en для всех новых строк, вкладка настроек «Диалог и диктовка» в существующей модалке (`createPortal`, `z-[9999]` — правило 19).

**ADR:** decision-30 (активация: автоповтор globalShortcut и wake word по транскрипту, с отвергнутыми альтернативами — uiohook-napi, приватное API рантайма computer-use, Porcupine/openWakeWord), decision-31 (схема ответа классификатора и одноразовый вызов модели).

## Что осталось непроверенным вживую

Всё, что требует слуха и микрофона: фактическая запись по удержанию клавиши, распознавание wake word, срабатывание barge-in, скачивание голоса Piper кнопкой с прогрессом (~64 МБ, голоса не скачаны), вывод в выбранное устройство (`setSinkId`), отсутствие реакции VAD на собственную речь, команды `read_tasks`/`read_doc`/`stop_reading` с загруженным голосом.

Пункты 4–5 проверены только по ветке отказа: `computerUse` на машине выключен (`computer-use.json` отсутствует), и включать его самостоятельно нельзя — правило 20 infra-dev и decision-27 п. 6.

Классификатор не проверен на живой модели: в `~/.projecthub/ai-config.json` провайдер `anthropic` без API-ключа, а этот путь намеренно не ходит через Claude CLI. На такой конфигурации `complete()` возвращает понятную ошибку, и рендерер показывает «Модель для разбора команд недоступна».

Дефекты TTS, найденные при разборе кода TASK-69, вынесены в TASK-87 и здесь не чинились.

Найдено при проверке владельцем (2026-09-16): push-to-talk не срабатывал — «открой задачи» не выполнялось.

Причина — гонка в `voiceService.beginPushToTalk()`. Метод ждал `startHandsFreeListening()`, а холодный старт занимает секунды (getUserMedia, AudioContext, воркер Whisper — 2381 мс по логу). Отпускание клавиши приходило раньше: `endPushToTalk()` видел `pushToTalkActive === false`, выходил вхолостую, после чего запуск всё-таки выставлял флаг — и режим записи залипал включённым навсегда. Первое нажатие гарантированно терялось.

Исправление: режим включается сразу при нажатии, у нажатия появилось «поколение» (`pushToTalkSeq`). Если клавишу отпустили во время старта, запуск отменяется и захват, открытый ради этого нажатия, закрывается. Залипание исключено.

По запросу владельца в ту же задачу добавлен крупный HUD распознанной речи (как в Talon Voice): системный оверлей переехал вниз по центру экрана и получил три режима — полоса 760×96, широкая полоса 1100×190 на время записи по горячей клавише (текст 34px) и окно 86%×60% экрана в режиме диктовки (текст 52px). Показывается распознанная фраза и итог команды. Окно не перехватывает фокус, поэтому в диктовке не мешает целевому приложению. Геометрию применяет main по полю `mode` в `voice:overlay-sync`.

Проверки после правок: tsc чисто, lint 0 ошибок / 503 предупреждения (базовый уровень), 86 файлов / 906 тестов, check-bundle чисто, pack:win пересобран (exe заменён, подтверждено временем модификации).

Отдельно выяснилось, почему трейс голосового конвейера не виден в логах упакованной сборки: `console.log` рендерера уходит в `logger.debug`, а минимальный уровень при `app.isPackaged` — `info`. Для диагностики нужен запуск с `PROJECTHUB_LOG_LEVEL=debug`.

## Final Summary

<!-- SECTION:FINAL_SUMMARY:BEGIN -->
Голосовое управление 2.0: глобальный push-to-talk, wake word по транскрипту, разбор свободных команд любой настроенной моделью, озвучка диалога с barge-in, голосовые команды компьютеру и системная диктовка.

**Новые чистые модули с тестами:** `pushToTalkPolicy` (детект удержания по автоповтору globalShortcut), `wakeWord` (сверка обращения по словам), `voiceCommandClassifier` (каталог интентов, промпт, толерантный парсер, LRU-кэш), `llmEndpoint` (адреса OpenAI-совместимых провайдеров), `bargeInDetector` (перебивание озвучки), `ttsSummary` (подготовка ответа агента к чтению вслух). Шесть новых тестовых файлов, +72 теста.

**Ключевые решения** зафиксированы в decision-30 и decision-31. Главные из них: удержание клавиши восстанавливается по автоповтору `RegisterHotKey` без единой новой зависимости (нативный хук отвергнут из-за `npmRebuild: false`); wake word считается по готовому транскрипту Whisper, без Porcupine и openWakeWord; контракт с моделью — один JSON-объект плюс запасной «голый идентификатор», без `response_format` и tool-use, которых нет у части провайдеров и локальных моделей.

**Вендор-нейтральность:** добавлен `aiAgentService.complete()` — одноразовый вызов без инструментов и без вендорской преамбулы, не ходящий через Claude CLI и не подставляющий вендорских дефолтов модели (decision-26 п. 0).

**Безопасность не ослаблена:** голос → компьютер и диктовка работают исключительно через `computerUseService.callTool`, где остаются HITL, allowlist, аудит и kill-switch; голосовой ход агента ограничен только инструментами `computer_*`; диктовка требует явного подтверждения при первом включении. Фичу `computerUse` задача не включает и включать не предлагает.

**Побочное улучшение:** голосовые «одобрить»/«отклонить»/«вариант N» теперь работают и для общей очереди HITL, а не только для карточек AI Studio, — запросы внешних сессий и `computer_action` от MCP-моста раньше голосом были недоступны.

Проверки: lint 0 ошибок (503 предупреждения — базовый уровень), 86 файлов / 906 тестов, `tsc` и `check-bundle` чисто, `pack:win` собран, регистрация глобальной клавиши подтверждена в упакованном приложении по `main.log`.

Непроверенным вживую осталось всё, что требует слуха и кликов: озвучка с голосами Piper (не скачаны), `setSinkId`, реакция VAD на собственную речь, wake word и barge-in, а также «счастливый путь» пунктов 4–5 — управление компьютером на машине выключено.
