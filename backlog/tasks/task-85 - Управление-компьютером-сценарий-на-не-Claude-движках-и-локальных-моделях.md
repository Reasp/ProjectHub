## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Вынесено из TASK-82 (2026-09-16) по решению пользователя: отладка управления компьютером на движках и моделях, отличных от Claude Code, делается отдельно. TASK-82 закрыта с этими двумя непроверенными критериями.

## Что осталось непроверенным

**AC #1 TASK-82 (частично)** — прокси `computer_*` подтверждён из Claude Code (внешний CLI через stdio-мост и Claude CLI в AI Studio) и из внешнего MCP-клиента. Не подтверждён из Codex CLI и Gemini CLI: на машине они не установлены.

**AC #5 TASK-82 (локальная модель без vision)** — сценарий «открыть Блокнот, напечатать текст, сохранить файл» на `qwen2.5:7b-instruct` (Ollama) не проходит. Две попытки 2026-09-16:
- попытка 1 (промпт по шагам): модель ~13 раз подряд вызвала выдуманный `computer_multi_edit` с несуществующими целями `com.example.myapp` и `com.microsoft.WindowsNotepad`; шаг 1 (`open_application` по allowlist) при этом отработал верно;
- попытка 2 (промпт с белым списком из пяти инструментов и явным запретом остальных): то же поведение, упор в лимит шагов 25, из 25 действий завершено 3.

Причина — следование инструкциям у 7B-модели, а не поведение прокси: каждый вызов вне allowlist корректно уходил в HITL и отклонялся (побочно подтверждает AC #2/#3 на плохо ведущей себя модели). Tool-loop API-агента при этом работает: результаты инструментов возвращаются модели.

## Направления
- Проверить модель покрупнее/с лучшим следованием инструкциям (локально или через OpenRouter/DeepSeek), прежде чем считать сценарий недостижимым для локальных моделей.
- Рассмотреть сокращение набора инструментов, отдаваемого слабым моделям: 61 схема `computer_*` в одном запросе — много для 7B.
- Изображения в результатах инструментов у OpenAI-совместимых провайдеров не передаются до флагов возможностей моделей (TASK-70).
- Codex/Gemini — только после установки соответствующих CLI.

См. [[decision-27]] (п. 10 и раздел проверок), TASK-70.
