## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Найдено при живой проверке TASK-69 (2026-09-17).

Если импортировать пару `.onnx` + `.onnx.json`, у которой имя файла совпадает со встроенным голосом из реестра (например, `ru_RU-irina-medium.onnx`), импортированный голос получает тот же идентификатор и выдаёт себя за встроенный: в списке он выглядит как установленный встроенный голос.

Хуже, когда проба в отдельном процессе ([[decision-34]]) отклоняет модель. `tts:importVoice` в `electron/ipc/ttsIpc.ts` вызывает `deleteVoice(installed.id)`, и тот удаляет каталог `<userData>/models/tts/<id>/`, где лежал **рабочий встроенный голос**. После неудачного импорта у пользователя пропадает голос, который работал.

## Что сделать
- Идентификатор импортированного голоса не должен пересекаться с реестром встроенных (`ttsVoiceRegistry`). Например, префикс `custom-` или суффикс при коллизии; решение принимает чистый модуль с тестами.
- Импорт не должен перезаписывать уже установленный голос: ни встроенный, ни ранее импортированный. Файлы сначала кладутся во временный каталог, и только после успешной пробы переносятся на место.
- Откат после неудачной пробы удаляет только то, что создал этот импорт.
<!-- SECTION:DESCRIPTION:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
## Что сделано

**Идентификатор.** Чистая функция `resolveImportedVoiceId(fileName, takenIds)` в `ttsVoiceRegistry`: имя встроенного голоса (и служебного `espeak-ng-data`) получает префикс `custom-`, занятое имя — суффикс `-2`, `-3`… Сравнение без учёта регистра: на Windows `RU_ru-IRINA-medium` и `ru_RU-irina-medium` — один каталог. Длина с префиксом и суффиксом не выходит за 64 символа.

**Staging до пробы.** `importVoiceFromFiles` заменён на `stageVoiceImport` → `{ voice, commit, discard }`:
- файлы пишутся в `.<id>.import` в корне кэша, голос до `commit` в списке не виден;
- id выбирается по занятым каталогам и активным импортам и резервируется синхронно, так что параллельные импорты одного файла получают разные id;
- `cleanupStaleTempArtifacts` знает про `.import` и не трогает активные импорты;
- `commit` пишет манифест с окончательными путями и переносит каталог целиком; на занятое место не переносит;
- `discard` удаляет только свой staging и после `commit` ничего не делает.

`importVoiceFromFiles` оставлен обёрткой «подготовить и сразу перенести».

`tts:importVoice`: проба идёт по путям staging. При отказе вызывается `discard`, `deleteVoice` больше не вызывается. `deleteVoice` остался только на случай, когда общий процесс синтеза не загрузил уже перенесённый голос. Id в этот момент только что создан этим импортом, поэтому чужие файлы откат не заденет.

- unit: 6 тестов `resolveImportedVoiceId`; интеграционные тесты `ttsVoiceStore` проверяют: откат оставляет в корне кэша прежний набор записей и не трогает встроенную Ирину (содержимое модели и `source: builtin`); успешный импорт не меняет встроенную; повторный импорт получает `-2` и его откат не задевает первый; параллельные импорты получают разные id; ошибка конфига не оставляет временных каталогов.
- tsc, eslint по изменённым файлам — чисто; vitest 96 файлов / 1040 тестов.
- Первый запуск `pack:win` упал на этапе `npm run build`, но отдельный `vitest run` сразу после этого прошёл полностью, и повторный `pack:win` собрался (exe 21:05). Причина первого падения не установлена, похоже на нестабильный тест.

- Битая модель `ru_RU-irina-medium.onnx` (2 МБ мусора): `{ok:false, errorCode:"model_rejected"}` (процесс пробы упал). Содержимое `models/tts` до и после одинаковое, sha256 модели встроенной Ирины `44c31fdb…` не изменился, `voice.json` — `source: builtin`.
- Рабочая модель (Руслан с HF) под именем `ru_RU-irina-medium.onnx`: `{ok:true, id:"custom-ru_RU-irina-medium"}`, проба 1,5 с, общий процесс загрузил голос за 1,2 с. В списке оба голоса: `ru_RU-irina-medium:builtin` и `custom-ru_RU-irina-medium:imported`, хэш встроенной Ирины прежний.
- После прогона тестовый голос удалён через `tts:deleteVoice`. localStorage голоса совпадает с бэкапом, язык интерфейса `en` — не менялись.

Остаток: голос, импортированный старой версией в каталог встроенного, так и останется встроенным по id. Автоматическая миграция не делалась, на этой машине таких каталогов нет.
